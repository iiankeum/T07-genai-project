# 업종 프로필

업종 프로필은 새 카드가 사용할 용어, 개념 간 관계, 품번·차번호 형식, 확정 필수 칸을 정의한다. 기본 프로필은 `automotive@1`이다. 서버에서 `AHMATDA_DOMAIN=automotive@1`을 설정하면 새 카드와 실시간 미리보기에 적용된다. 카드에는 그 프로필 버전이 저장된다. 이전 데이터베이스의 카드는 마이그레이션에서 `automotive@1`로 등록된다.

| 프로필 항목 | 사용하는 곳 |
| --- | --- |
| `sttContext` | 음성 인식 힌트와 카드 추출의 업무 맥락 |
| `concepts` | 추출 모델이 참고하는 개념 ID, 표준 이름, 별칭 |
| `relations` | 추출 모델이 참고하는 개념 간 관계 |
| `partNoCue`, `partNoTypical` | 통화에서 불러 준 품번 대조와 품번 형식 경고 |
| `orderFields`, `itemFields` | 편집 화면의 이름과 주문 확정 필수값 안내 |
| `textLimits`, `modelYearPattern` | 입력 최대 길이와 연식 형식 |
| `partNoPattern`, `platePattern`, `qtyMin`, `qtyMax` | 서버와 화면이 공통으로 사용하는 입력 규칙 |

워크스페이스에서 승인한 현장말·오인식·거래처·차종도 음성 인식과 카드 추출에서 참조한다. 프로필은 배포 단위, 승인 지식은 워크스페이스 단위로 관리한다.

## 프로필 추가 예시

창고 자재 접수라면 [domain.js](../public/js/domain.js)에서 `automotive`를 복사해 새 프로필 ID를 만든다. `concepts`의 `carModel`을 ‘장비 모델’로 부르고 `part`와의 관계를 ‘호환 장비’로 바꿀 수 있다. `orderFields`에는 `customer: '사업장'`, `carModel: '장비 모델'`을 지정한다. `partNoCue`와 품번 정규식을 현장 자재 코드에 맞추고, 차량 번호 형식을 검사하지 않는 프로필은 `platePattern: null`을 사용한다. `DOMAINS`에 등록한 뒤 그 ID로 서버를 재시작한다. 각 관계의 `source`와 `target`은 같은 프로필 안의 개념 ID를 참조한다.

프로필 편집은 기존 카드의 필드 키와 지원하는 값의 종류 안에서 작동한다. 새 칸을 추가하는 업종은 SQLite 스키마, 추출 JSON 스키마, 카드 화면, 내보내기를 함께 확장해야 한다. 기존 카드도 열 수 있도록 이미 사용한 프로필 버전은 보관하고, 규칙이 바뀌면 새 ID를 추가한다.
