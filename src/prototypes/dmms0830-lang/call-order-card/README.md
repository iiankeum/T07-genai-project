## 확인하려던 것

투표 결과 글에 적힌 질문이다.

> 헤드셋 낀 일반 전화 음질에서 STT가 현장 용어·차번호·수량을 제대로 알아듣는지

## 흐름

1. 녹음 파일이나 녹음이 쌓이는 폴더를 넘긴다
2. 음성 인식(Whisper large-v3)이 **PC 안에서** 통화를 글로 옮긴다. 녹음은 밖으로 나가지 않는다
3. 생성형 AI(Claude)가 받아쓴 글에서 주문 카드를 뽑는다 — 거래처 · 차종 · 연식 · 차번호 · 부품 · 수량 · 품번(불러 준 경우만) · 급한지 · 다시 물어볼 것
4. 카드 화면(`out/cards.html`)에서 담당자가 글자를 눌러 고치고 「확정」을 누른다
5. 화면 위쪽에 하루 요약이 나온다 — 주문 통화 수 · 급한 주문 · 아직 확정 안 한 카드 · 다시 전화할 곳

AI 가 틀리기 쉬운 곳을 줄이려고 세 가지를 넣었다.

- **낱말 사전**(`data/glossary.txt`) — 휀다·쇼바·라지에다 같은 현장 말. 음성 인식에는 힌트로, AI 에는 고쳐 읽을 기준으로 준다
- **거래처 목록**(`data/customers.txt`) — 받아쓴 상호를 목록의 표기로 맞춘다
- **「들어 보기」 표시** — 받아쓴 글자가 틀렸을 수 있는 값(차번호 한글 빠짐, 품번 자릿수 이상)은 AI 가 지어내지 않고 표시만 한다. 담당자가 녹음의 그 대목을 듣고 정한다

품번은 AI 가 찾거나 지어내지 않는다. 통화에서 불러 준 품번만 적고, 나머지는 사람이 정한다.

## 결과

가짜 주문 통화 10건(부품 18줄, 차번호 4건, 품번 2건)을 만들어 정답 카드와 비교했다. 숫자는 `맞은 수/전체 수`다.

| 항목 | 깨끗한 음성 · 도움 없음 | 전화 음질 · 도움 없음 | 전화 음질 · 사전 | 전화 음질 · 사전 + 거래처 목록 | 잡음 심한 전화 · 사전 + 거래처 목록 |
|---|---|---|---|---|---|
| 거래처 | 7/10 | 7/10 | 7/10 | 9/10 | 9/10 |
| 차종 | 10/10 | 9/10 | 10/10 | 10/10 | 10/10 |
| 연식 | 10/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| 차번호 | 9/10 | 9/10 | 9/10 | 9/10 | 9/10 |
| 부품 | 18/18 | 18/18 | 18/18 | 18/18 | 18/18 |
| 수량 | 18/18 | 18/18 | 18/18 | 18/18 | 18/18 |
| 품번 | 17/18 | 18/18 | 17/18 | 17/18 | 18/18 |
| 급함 | 10/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| 되물음 판정 | 10/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| 카드 전체가 정답 | 5/10 | 6/10 | 5/10 | 7/10 | 8/10 |
| 표시 없이 틀린 카드 (적을수록 좋음) | 1/10 | 3/10 | 1/10 | 0/10 | 0/10 |

- 마지막 줄은 11/27 에 같은 결과를 다시 센 것이다. 틀린 칸 가운데 하나라도 「들어 보기」 표시가 짚지 않은 카드 수다([다시 센 결과](results/표시없이-틀린-카드-2026-11-27.md))
- 「전화 음질」은 합성 음성을 300~3400Hz · 8kHz 로 좁히고 잡음을 섞은 것이다. 「잡음 심한 전화」는 대역을 더 좁히고 잡음을 4배로 했다
- 차번호와 품번은 말하지 않은 통화에서 비워 둔 것도 맞은 것으로 셌다
- 틀린 곳과 받아쓴 글 전체는 [results/eval-2026-11-11.md](results/eval-2026-11-11.md)에 있다

읽는 법은 이렇다.

- **부품 · 수량 · 연식 · 급함은 모든 조건에서 전부 맞았다.** 사전 없이 돌리면 음성 인식이 현장 말을 「헨더 · 압쇼바 · 활데링크 · 세로모터」로 받아쓰지만, AI 가 휀다 · 앞쇼바 · 활대링크 · 세루모터로 고쳐 읽었다. "열 개, 아니다, 스무 개"처럼 고쳐 말한 수량도 맞혔다
- **약한 곳은 세 가지다.**
  1. 거래처 이름 — 새한 → 세안, 제일 → 제1, 한빛 → 한비. 고유명사는 음성 인식이 맞힐 근거가 없다. 거래처 목록을 주면 7건 → 9건으로 오른다. 남은 1건은 목록에 비슷한 이름이 둘(한빛카 · 한일카) 있어서 AI 가 고르지 않고 표시만 했다
  2. 차번호 가운데 한글 — "육십칠 저 팔구공일"을 `67-8901`로 받아썼다. 네 건 중 한 건이다
  3. 품번 — 두 건 중 한 건이 돌릴 때에 따라 한 자리가 더 붙었다(`58101-D4AE15`)
- **사전과 거래처 목록을 준 조건에서는 틀린 값에 모두 「들어 보기」 표시가 붙었다.** 차번호는 비워 두고, 품번은 "자릿수가 보통과 다르다"고 적었다. 표시 없이 틀린 카드는 없었다. 도움 자료가 없을 때는 "세안 카센터"처럼 표시 없이 틀린 것이 있었다. 다섯 조건을 합쳐 5건이고 모두 거래처 이름이다. 품번 · 차번호 오답은 형식이 이상해서 모두 표시가 붙었다
- 속도 — 통화 10건(4분 41초)을 받아쓰는 데 17초 걸렸다(RTX 5060 Ti). CPU 로 돌리면 24초짜리 통화 한 건에 28초다. 카드 뽑기는 건당 10초 안쪽이다

## 한계

숫자가 좋아 보이지만 그대로 믿으면 안 된다.

- **합성 음성이다.** 사람 목소리보다 또박또박해서 실제 통화보다 쉽다. 잡음을 4배로 올려도 결과가 나빠지지 않았는데, 이는 이 시험이 실제 통화의 어려움(웅얼거림, 사투리, 말 겹침, 공장 소음)을 드러내지 못한다는 뜻이다
- **10건뿐이다.** AI 답은 돌릴 때마다 한두 칸씩 달라진다
- **같은 10건을 보면서 AI 지시문을 고쳤다.** 새 통화에서는 점수가 내려갈 수 있다
- 양쪽 목소리를 나누지 않는다. 누가 말했는지는 AI 가 내용으로 짐작한다
- 카드를 고치거나 확정해도 저장되지 않는다. 화면만 있다
- 윈도우 PC 한 대(RTX 5060 Ti)에서만 돌려 봤다. CPU 로는 받아쓰기 한 건만 확인했다(`ORDER_CARD_DEVICE=cpu`)

## 실제 녹음으로 시험할 때

아이디어 문서의 검증 방법(실제 대리점 통화 녹음으로 시험)을 하려면 아래를 먼저 정해야 한다.

- 녹음은 `real/` 폴더에 넣는다. 이 폴더는 `.gitignore` 에 있어서 저장소에 올라가지 않는다
- **받아쓰기는 PC 안에서 끝나지만, 받아쓴 글은 Claude(해외 서버)로 간다.** 실제 통화에는 거래처 이름·차번호·사람 이름이 들어 있다. 대리점의 동의를 받거나, 이름과 번호를 가리고 보내거나, 카드 뽑기도 PC 안의 AI 로 바꿔야 한다
- 실제 녹음, 받아쓴 글, 카드(`out/`)는 저장소에 올리지 않는다. 맞힌 비율 같은 숫자만 공유한다

## 실행 방법

준비물: Python 3.10 이상, [ffmpeg](https://ffmpeg.org/), 로그인된 [Claude Code](https://claude.com/claude-code). NVIDIA 그래픽카드가 있으면 빠르다.

```
cd src/prototypes/dmms0830-lang/call-order-card
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-gpu.txt     # NVIDIA 그래픽카드가 있을 때만
python make_samples.py                  # 가짜 통화 음성 만들기 (인터넷 필요)
python ordercard.py samples/phone       # 카드 화면: out/cards.html
python evaluate.py                      # 정답과 비교: out/eval.md
```

- 처음 실행할 때 음성 인식 모델(약 3GB)을 내려받는다
- 내 녹음으로 해 보려면 `python ordercard.py 녹음폴더` 처럼 폴더나 파일을 넘긴다. m4a · mp3 · wav · amr 등 ffmpeg 가 읽는 형식이면 된다
- 가짜 통화 음성(`samples/`)은 합성 서비스로 만든 것이라 저장소에 올리지 않았다. `make_samples.py` 로 다시 만든다
