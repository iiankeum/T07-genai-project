# 단체 식사 예약 도우미 AI — 프로토타입

회식·거래처 식사·부서 모임 장소를 정할 때, 단체 채팅방 의견을 모아 **식당 후보 3곳**을 비교해 준다.
아이디어 문서: [docs/ideas/남희-단체 식사 예약 도우미 AI.md](<../../../docs/ideas/남희-단체 식사 예약 도우미 AI.md>)

```
단체방 의견 ──▶ 생성형 AI: 조건 정리 ──▶ 코드: 식당 거르기·점수·금액 ──▶ 후보 3곳 ──▶ 팀원 투표 ──▶ 담당자 결정·예약
 (카톡 붙여넣기)   (필수 / 선호 / 뺌)       (가상 식당 데이터 21곳)         (예상 총액·이유·확인할 것)  (공유 링크)   (캐치테이블·매장 확인)
                     ▲                                                      │
                     └──── 의견이 바뀌면 다시 정리하고 '무엇이 달라졌나' 설명 ◀──┘
```

## 바로 실행 (API 키 없이 3분)

```bash
cd src/prototypes/group-dining-helper
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

http://localhost:5000 에서 **11월 팀 회식 (예시) → 불러오기**를 누른다.
왼쪽 아래 예시 의견 **“+ 지영: 룸이 없어도 걸어서 갈 수 있는 곳이 좋아요”**를 누르면 후보 순서가 바뀌고 이유가 나온다.

## 하는 일

| 아이디어 문서의 항목 | 프로토타입에서 |
|---|---|
| 평소 말하듯 입력하면 의견을 모아 후보 최대 3곳 비교 | 한 줄에 하나씩 `이름: 내용`, 또는 카톡 대화 내보내기(PC·모바일 형식)를 그대로 붙여 넣는다 |
| 예산·먹을 수 있는 메뉴는 필수, 룸은 선호로 구분 | 조건 표에 필수 / 선호(중요도 조금·보통·높음) / 뺌으로 나뉘고, 누가 한 말인지 근거가 붙는다. 담당자가 버튼으로 바꿀 수 있다 |
| 예상 총액과 추천 이유, 확인이 필요한 사항 따로 표시 | 후보마다 총액(기준 메뉴 인당 × 인원, 주류 포함 여부), 추천 이유, 아쉬운 점, **확인 필요**(8인 룸 빈자리, 룸 최소 주문, 예산 여유 없음 등) |
| 공유 링크로 투표, 담당자가 캐치테이블에서 확인·예약 | 로그인 없는 투표 링크(한 사람 한 표, 다시 투표하면 바뀜). 결정하면 캐치테이블 버튼·예약 확인 목록·단체방 공지 문구가 나온다 |
| 의견이 바뀌면 순서를 조정하고 달라진 점 설명 | 의견을 넣을 때마다 다시 계산하고 “1위가 A → B로 바뀌었습니다” + 조건 변화 + 식당별 점수 변화를 보여 준다. 투표 때 남긴 의견도 버튼 하나로 조건에 반영 |
| 가격·좌석은 바뀔 수 있음 | 금액 옆에 기준 메뉴와 가격 기준일을 늘 함께 표시. 예약 가능 여부는 캐치테이블·매장에서 최종 확인하라고 안내 |
| 걸린 시간·놓친 조건 수 비교 (홍보·검증) | 결정 화면에 “모임을 만들고 n분 만에 결정 · 의견 n개 · 반영한 조건 n개 · 후보 조정 n회 · 투표 n명” |

그 밖에:
- **조건으로 못 바꾼 의견**(예: “케이크 가져가도 되나요?”)은 따로 모아 보여 주고, 예약 확인 목록에도 넣는다.
- **예산을 조금만 올리면 갈 수 있는 곳**(10% 이내 초과)을 알려 준다.
- **조건 때문에 빠진 식당**과 빠진 이유(목요일 휴무, 단체 최대 6명, 회 없이 먹을 메인 없음 …)를 모두 볼 수 있다.

## AI가 하는 일과 하지 않는 일

- **AI(생성형)**: 두서없는 단체방 의견을 조건 목록(JSON)으로 정리한다. 앞 의견을 뒤 의견이 바꾸는 것(“룸 없어도 돼요”)도 판단한다.
- **코드**: 식당 거르기, 점수, 금액 계산, 달라진 점 설명은 정해진 규칙으로 한다. 그래서 AI가 없는 식당이나 틀린 가격을 지어낼 수 없다.
  AI가 낸 조건도 코드가 검사해서 데이터에 없는 역·업종, 모르는 조건 종류는 버린다.

## AI 켜기

`.env.example`을 `.env`로 복사하고 `LLM_PROVIDER`를 바꾼다.

| 설정 | 단체방 의견이 PC 밖으로 나가나 |
|---|---|
| `LLM_PROVIDER=rule` (기본) | 안 나감 — 규칙 기반, 키 불필요 |
| `LLM_PROVIDER=ollama` ([Ollama](https://ollama.com) 설치 후 `ollama pull qwen2.5:7b`) | 안 나감 |
| `LLM_PROVIDER=anthropic` (`ANTHROPIC_API_KEY`) 또는 `openai` (`OPENAI_API_KEY`) | 나감 |

AI 호출이 실패하면 규칙 기반 정리로 자동 대체하고 화면에 그 사실을 표시한다.

## 팀원 휴대폰에서 투표해 보기

같은 와이파이에서 `HOST=0.0.0.0 python app.py`로 실행하고, 투표 링크의 `localhost`를 노트북 IP(예: `192.168.0.12`)로 바꿔 공유한다.
밖에서도 열려면 Render·Railway 같은 곳에 올리거나 터널(ngrok 등)을 쓴다.

## 우리 회사 주변 식당으로 바꾸기

[`data/`](data/)의 `restaurants.csv`, `menus.csv`를 엑셀로 고치면 된다. 열 설명은 [data/README.md](data/README.md).

## 구조

```
app.py                 웹 화면 (Flask) — 담당자 화면, 투표 화면
data/                  가상 식당 21곳 · 메뉴 83개 (CSV)
samples/               예시 모임 2개 (팀 회식, 거래처 점심)
dining_ai/
  parse.py             생성형 AI로 의견 → 조건 정리 + 결과 검사 + 실패 시 규칙 기반 대체
  parse_rules.py       규칙 기반 조건 정리 (키 없이 동작, 비교 기준)
  llm.py               AI 호출 (anthropic · openai · ollama, SDK 없이 urllib)
  engine.py            필수 조건 거르기, 선호 점수, 예상 금액, 추천 이유·확인 필요
  changes.py           이전 결과와 비교해 '무엇이 달라졌나' 설명
  service.py           모임 흐름 (의견 추가·조건 수정·투표·결정·예약 안내), 카톡 붙여넣기 해석
  store.py             SQLite 저장 (모임·의견·결과 기록·투표)
  models.py, data.py   자료 구조, CSV 읽기
tests/                 pytest
```

## 아직 안 한 것

- 실제 회식 준비 경험자에게 써 보게 하고 기존 방식과 시간·놓친 조건 수 비교
- 생성형 AI 정리 vs 규칙 기반 정리 비교표 (같은 단체방 의견, 조건별 정답률)
- 식당 데이터 자동 수집, 캐치테이블 빈자리 조회 (지금은 사람이 확인)
- 투표 마감 시간·익명 투표, 모임 날짜 후보 투표
