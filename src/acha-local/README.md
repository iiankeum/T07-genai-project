# 아차(로컬) — 단어장을 끼워 PC 안에서 받아쓰는 프로그램

녹음(회의 · 수업 · 전화)을 **인터넷 없이 내 PC 안에서** 받아쓰고, **내 단어장**(고유명사 · 전문 용어 · 현장말)을 끼워 그 낱말을 바르게 적는 Windows 프로그램이다.

자동차 부품 대리점 전화 주문을 받아쓰는 서비스 「아차」([`src/app`](../app))의 받아쓰기 원리를, 어떤 녹음 · 어떤 단어장에도 쓸 수 있게 떼어 낸 것이다. 아차는 이 원리를 실제 업무에 적용한 사례다.

- 녹음 파일을 넣거나 바로 녹음해서 받아쓴다(mp3 · m4a · wav · mp4 · webm …).
- 단어장의 낱말을 **30초마다** 엔진에 알려 주고, 받아쓴 뒤 단어장으로 **한 번 더 고친다**.
- 틀린 말을 고르고 바른 말을 적으면 단어장이 **배운다** — 다음 녹음부터 바로 고쳐진다.
- 같은 녹음을 네 가지 방법으로 받아써서 **단어장 효과를 숫자로** 볼 수 있다.
- 녹음 · 단어장 · 받아쓴 글은 이 PC(`%LOCALAPPDATA%\AchaLocal`)에만 남는다.

## 설치

1. [Releases](https://github.com/iiankeum/T07-genai-project/releases) 에서 `AchaLocal-Setup-0.1.0.exe`(68MB)를 받아 실행한다. Windows 10 · 11 64비트, 관리자 권한은 필요 없다.
   - 코드 서명을 하지 않아 「Windows의 PC 보호」 창이 뜰 수 있다 → **추가 정보 → 실행**.
2. 처음 열면 **설정 → 받아쓰기 모델**에서 `large-v3-turbo`(1.6GB)를 받는다. 처음 한 번만 인터넷을 쓴다.
   - 인터넷이 안 되는 PC 는 다른 PC 에서 받은 모델 폴더를 복사해 와서 「인터넷이 안 되는 PC 라면」에 경로를 적는다.
3. NVIDIA 그래픽카드가 있으면 **설정 → GPU 가속 받기**(약 1.3GB · NVIDIA 공식 배포본)를 누른다. 받아쓰기가 20배쯤 빨라진다(아래 「속도」). 받은 뒤 프로그램을 한 번 닫았다가 다시 연다.

지울 때는 시작 메뉴의 「아차(로컬) 지우기」. 내 자료(`%LOCALAPPDATA%\AchaLocal`)는 남으니 필요 없으면 직접 지운다.

## 쓰는 법

1. **단어장**에서 낱말을 적는다. 엑셀 CSV 나 한 줄에 하나씩 적은 글 파일을 「가져오기」 해도 된다.
   - **낱말**: 글에 이렇게 적혀야 하는 모양(예: `라디에이터`)
   - **다르게 들리는 말**: 엔진이 잘못 적는 모양이나 현장에서 부르는 말(예: `라지에다, 라지에타`). 보이면 낱말로 바꾼다.
   - **항상**: 힌트 자리가 모자라도 먼저 넣는다(거래처 이름 · 사람 이름처럼 꼭 맞아야 하는 것).
2. **받아쓰기**에서 녹음을 넣고 단어장을 고른다. 「이 녹음은…」에 한 줄 설명(예: `경영학원론 3주차 수업입니다.`)을 적으면 더 잘 알아듣는다.
3. 받아쓴 글에서 <mark>초록</mark>은 고친 곳(누르면 되돌림), <mark>노랑</mark>은 「고칠까요?」 제안(누르면 고치고 단어장이 배움)이다. 시간을 누르면 그 자리부터 들린다.
4. 틀린 말을 마우스로 고르면 **단어장에 넣기**가 뜬다. 바른 말을 적으면 단어장에 쌓이고 이 글도 바로 고쳐진다.
5. 글(.txt) · 자막(.srt) · 마크다운으로 저장하거나 복사한다.

## 원리

받아쓰기 엔진은 [faster-whisper](https://github.com/SYSTRAN/faster-whisper)(OpenAI Whisper 를 빠르게 돌리는 것)다. 엔진은 고칠 수 없으니, **엔진에게 무엇을 언제 알려 주느냐**와 **받아쓴 뒤 무엇을 고치느냐**로 정확도를 올린다.

| 단계 | 하는 일 | 왜 |
|---|---|---|
| ① 힌트 고르기 | 단어장에서 「항상 → 많이 쓰인 낱말 → 단어장 순서」로 골라 **223 토큰** 안에 넣는다. | 엔진이 한 번에 받는 힌트 자리는 문맥 창(448)의 절반 - 1 = 223 토큰이고, 넘치면 잘린다. 한국어는 거의 한 글자가 한 토큰이라 낱말 **40개 안팎**만 들어간다(부품 · 차종 56개로 재 보니 38개째에서 넘침). |
| ② 30초마다 알려 주기 | 힌트를 `hotwords` 로 넘긴다. | 흔히 쓰는 `initial_prompt` 는 `condition_on_previous_text=False` 일 때 **첫 30초에만** 들어간다(faster-whisper 1.2.1 `transcribe.py` 에서 확인). `hotwords` 는 30초 창마다 다시 넣는다. |
| ③ 두 번 듣기 | 단어장이 힌트 자리보다 크면, 1차로 받아쓴 글에 (그대로든 비슷한 소리로든) 나온 낱말을 먼저 넣어 다시 받아쓴다. | 거래처 1,000곳처럼 단어장이 커도 그 녹음에 나온 낱말이 자리를 얻는다. 시간은 2배. |
| ④ 받아쓴 뒤 고치기 | 다르게 들리는 말 → 낱말, 띄어쓰기 맞추기, **자모 단위 소리 비교**로 낱말과 아주 비슷한 곳을 찾는다. 길고 아주 비슷하면 자동, 아니면 제안. | 엔진이 힌트를 받아도 틀리는 말이 남는다. 인터넷 · AI 없이 규칙만으로 고친다(`라` 와 `나` 는 글자로는 다르지만 자모로는 첫소리 하나만 다르다). |
| ⑤ 배우기 | 사람이 고친 말을 단어장의 「다르게 들리는 말」로 쌓고, 받아쓴 글에 나온 낱말의 「쓰인 횟수」를 올린다. | 다음 녹음부터 ④에서 바로 고치고, ①에서 자주 쓰는 낱말이 먼저 자리를 얻는다. |

## 효과 (재 본 숫자)

정답을 아는 **가짜 녹음 2개**(합성 목소리 · 내용 지어냄 · [`samples/`](samples))를 네 가지 방법으로 받아썼다. 프로그램의 「효과 재기」 화면과 `tools/eval.py` 가 같은 계산을 한다. NVIDIA RTX 5060 Ti.

**부품 주문 전화**(83초 · 전화선처럼 좁힌 소리 · 단어장 63개)

| 방법 | large-v3-turbo 글자 오류율 | 단어장 낱말 맞힘 | large-v3 글자 오류율 | 단어장 낱말 맞힘 |
|---|---|---|---|---|
| 단어장 없이 | 9.4% | 16/28 | 11.5% | 16/28 |
| 첫머리 힌트만(`initial_prompt`) | 7.4% | 22/28 | 8.8% | 23/28 |
| 30초마다 힌트(`hotwords`) | 6.1% | 25/28 | 6.7% | 26/28 |
| **힌트 + 고치기** | **5.1%** | **26/28** | **5.7%** | **27/28** |

**AI 수업 강의**(72초 · 단어장 37개)

| 방법 | large-v3-turbo 글자 오류율 | 단어장 낱말 맞힘 | large-v3 글자 오류율 | 단어장 낱말 맞힘 |
|---|---|---|---|---|
| 단어장 없이 | 2.3% | 25/28 | 2.6% | 25/28 |
| 첫머리 힌트만 | 2.0% | 26/28 | 2.0% | 26/28 |
| 30초마다 힌트 | 1.1% | 27/28 | 0.0% | 28/28 |
| **힌트 + 고치기** | **0.0%** | **28/28** | **0.0%** | **28/28** |

- 30초 뒤에 나오는 낱말(「한빛모터스」 · 「블로워모터」)은 **30초마다 힌트**에서만 맞았다 — ②의 근거.
- 한계: 합성 목소리라 실제보다 쉽다. 녹음이 하나씩뿐이다. 단어장을 녹음 내용을 알고 만들었다. **실제 녹음으로 다시 재야 한다** — 프로그램의 「효과 재기」에 내 녹음과 사람이 적은 정답 글을 넣으면 된다.

## 속도

재 본 PC: AMD Ryzen 5 7500F(6코어) · NVIDIA RTX 5060 Ti 16GB · 모델 large-v3-turbo.

| 어디서 | 재 본 것 | 걸린 시간 | 녹음 1시간이면(어림) |
|---|---|---|---|
| 그래픽카드(GPU 가속 받은 설치본) | 83초 전화, 두 번 듣기 포함 | 4.3초 | 3~4분 |
| CPU 만(6코어 · 설치본) | 72초 강의, 두 번 듣기 포함 | 88.7초 | 한 번만 들어도 35~40분 |

- CPU 는 녹음 길이의 0.6배쯤 걸린다(한 번 듣기 · 힌트 포함). 그래서 CPU 로 10분 넘는 녹음은 두 번 듣기를 하지 않는다. NVIDIA 그래픽카드가 있으면 「GPU 가속 받기」를 권한다.
- CPU 일꾼 수는 실제 코어 수(논리 코어의 절반, 최대 8)로 잡는다. 논리 코어를 다 쓰면 오히려 느렸다.
- 모델이 클수록 정확하고 느리다: `small`(빠름) · `large-v3-turbo`(권장) · `large-v3`(가장 정확, GPU 에서 turbo 의 약 3배 시간).

## 원리만 갖다 쓰기 (Python)

`glossary_stt/` 는 프로그램과 떨어져 쓸 수 있다. 화면 없이 원리만 쓰려면:

```python
from faster_whisper import WhisperModel
from glossary_stt import Glossary, Corrector, plan_hints, apply
from glossary_stt.hints import tokenizer_counter

model = WhisperModel("large-v3-turbo", device="cuda", compute_type="float16")
g = Glossary.from_csv("내 단어장", open("words.csv", encoding="utf-8-sig").read())
plan = plan_hints(g, "자동차 부품 주문 전화입니다.", tokenizer_counter(model.hf_tokenizer))  # ① 223 토큰 안에서 고르기

segments, _ = model.transcribe("call.mp3", language="ko", hotwords=plan.hotwords,           # ② 30초마다
                               condition_on_previous_text=False, vad_filter=True)
fix = Corrector(g)
for s in segments:
    print(apply(s.text, fix.find(s.text)))                                                   # ④ 받아쓴 뒤 고치기
```

두 번 듣기(③)까지 하려면 `glossary_stt.pipeline.run(...)` 을 쓴다. 단어장 CSV 머리줄은 `낱말,다르게 들리는 말,메모,항상 넣기,쓰인 횟수`(영문 `term,aliases,note,pinned,hits` 도 됨).

## 아차에 쓰인 모습 (적용 사례)

아차는 대리점 전화를 받아써서 주문 카드를 만든다. 낱말 사전(F07 · 현장말 · 오인식 · 거래처 · 차종)을 두 군데에 쓴다.

1. 받아쓰기 일꾼(`src/pc-agent`)에 `initial_prompt` 로 현장말을 넘긴다(`src/app/lib/repo.mjs` `dictionaryForAi`, 600글자).
2. 카드를 만들 때 AI 가 사전을 보고 고쳐 읽는다(`src/app/lib/ai.mjs`).

이 프로그램을 만들며 알게 된 것 — 아차에도 옮기면 좋다(아직 옮기지 않음):

- 600글자를 보내지만 엔진에는 **223 토큰(약 40낱말)** 만 들어가고, 넘치면 **앞에서부터** 잘린다(업무 설명 문장이 먼저 사라진다).
- 일꾼이 `condition_on_previous_text=False` 라 사전 힌트가 **통화 첫 30초에만** 쓰인다. 평균 80초 통화라 뒷부분 부품 이름에는 힌트가 닿지 않는다. → `hotwords` 로 바꾼다.
- 전화번호로 거래처를 알면 그 거래처 상호 · 자주 시키는 부품을 먼저 넣는다(①의 「항상」 · 「쓰인 횟수」와 같은 생각).

## 개인정보 · 인터넷

- 이 PC(127.0.0.1)에서만 열리고, 실행할 때마다 바뀌는 비밀 표가 있어야 화면이 서버와 말한다.
