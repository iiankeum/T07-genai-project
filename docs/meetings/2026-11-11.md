## 논의 내용
- **아이템** — 7번 「AI 전화 주문 받아쓰기」로 정했다.
- **문제** — 기본 통화 녹음은 파일이 시간순으로만 쌓여 이름만으로 내용을 알 수 없고, 원하는 통화를 찾으려면 처음부터 들어야 한다. 통화가 많고 받아쓴 글이 필요한 고령 사용자, 특히 현대모비스 부품 대리점 부장님들이 통화 내용을 빨리 찾아 주문 여부와 사실관계("두 개라고 했다 / 안 했다")를 확인하게 돕는 것이 핵심이다.
- **목표 경험(개발 쪽 시안)** — 말하는 즉시 대화가 화면에 써지고, 중요한 내용이 색으로 표시돼 주문 카드로 모인다. 용어집, 대시보드, 통화 기록을 바탕으로 한 할 일 추천, 지난 통화에 대한 질문 기능도 구상했다. 시안은 화면만 있고 기능은 없다.
- **녹음 가져오기** — 대리점 상담 전화기에서는 주문 통화가 이미 녹음돼 정해진 폴더에 저장된다. 각 PC 에 프로그램을 깔아 새 녹음이 생기면 서버로 보내고, 서버에서 받아쓰고 분석한다(프린트 자료를 모아 서버로 보내는 기존 방식과 비슷). 실시간 받아쓰기도 가능성은 있으나, 스피커 · 마이크 소리를 기준으로 녹음을 시작하는 규칙을 정하고 현장에서 확인해야 한다.
- **음성 인식** — API 는 비용이 들고 여러 회사에 깔려면 PC 안 모델이 맞을 수 있다. 갤럭시 통화 후 자동 전사와 Whisper 같은 설치형 모델을 둘 다 시험해 성능이 좋은 쪽을 고른다.
- **개발 · 배포** — 기획 초안을 바탕으로 프로그램을 만들고, GitHub 의 변경이 서버에 반영돼 데모 사이트가 갱신되게 한다. 남는 AWS 서버를 쓴다. 회사마다 설치할 수 있는 구성도 고려한다.
- **제품명** — 「콜노트」가 나왔지만 의견이 갈렸다. 기획서가 나온 뒤 맥락을 보고 후보를 내 투표한다. 그 전까지 기획서의 제품명은 비워 둔다.
- **마케팅** — 개발이 49주차에 끝나면 홍보 기간이 1~2주뿐이라 47주차부터 프리마케팅을 한다. 동작하는 데모와 소개 페이지를 SNS · 동종 업계 오픈 채팅방에 알리고 무료 체험 신청을 받는다. 팀원의 실제 업무 사례를 중심으로 알리고, 과제 평가를 위해 사례를 지어내지 않는다.
