# Mac 설치 경험과 릴리즈 계획

## 목표와 참고 범위

목표는 **Mac 앱 설치 → 최초 모델 준비 → 로컬 기본 사용**이다. 사용자에게 Docker·Node·Ollama·Python의 수동 설치나 터미널 실행을 요구하지 않는다. 팀 서버 연결은 설정의 별도 선택이다. 현재 Node와 선택 Ollama 런타임 번들·첫 실행 설치·모델 준비 메뉴를 구현했다. 선택 Python/Whisper 번들과 관리자 연결 기반 자동 일꾼까지 구현했다. 전체 신규 설치 경험은 남아 있어 목표 전체를 달성하지 않았다.

사용자가 지칭한 Alt는 문맥상 [Alt 필기앱](https://altalt.io/ko/)으로 추정한다. 링크를 사용자에게 확정받은 것은 아니다. 2026-11-18 공식 FAQ는 Apple Silicon의 로컬 전사, 로컬 AI와 선택 클라우드 기능, 기기 안 저장을 설명한다. 이는 설치 경험의 참고 자료이며 Alt 앱을 설치·분석하거나 내부 모델 설치기를 검증한 결과가 아니다.

[Lightning-SimulWhisper README](https://github.com/altalt-org/Lightning-SimulWhisper)는 Alt 앱 전체 소스가 아닌 전사 엔진이라고 밝힌다. [LICENCE.txt](https://github.com/altalt-org/Lightning-SimulWhisper/blob/main/LICENCE.txt)는 PolyForm Noncommercial 1.0.0이다. 이 저장소의 코드·바이너리를 아맞다의 상용 대리점 제품에 포함하지 않는다. 아래 설치 마법사는 아맞다의 제안이다.

## 최초 실행 화면

1. **이 Mac에서 시작**을 기본으로 제시한다. 기종·OS·메모리·남은 저장 공간을 검사한다. 미지원 기기에는 이유와 수동 업무 사용을 제공하며 유료 클라우드로 자동 전환하지 않는다.
2. **모델 준비** 화면에서 전사 모델과 주문 정리 모델을 나누어 이름·버전·라이선스·실제 다운로드 바이트·필요 저장 공간·다운로드 서버를 보여 준다. 모델 파일을 받는 연결이며 사용자의 녹음·원문은 전송하지 않는다고 구분한다.
3. **내려받기**는 명시적인 시작 이후 진행한다. 모델별 진행률·남은 용량·일시 정지·취소·재시도를 제공한다. 앱을 재실행해도 이어 받는다. 다운로드 실패·손상·디스크 부족 때 기존 정상 모델을 보존한다.
4. **로컬 준비 확인**은 내장 가짜 음성으로 전사와 주문 카드 생성이 실제로 끝나는지 확인한다. 파일 존재만으로 완료 표시하지 않는다. 이후 인터넷을 끊어 같은 흐름을 검증한다.
5. **업무 시작**에서 업종을 선택한다. 업종별 용어·필드·필수값·검토 규칙은 기존 버전 있는 프로필 경계를 사용한다. 첫 지원 업종은 자동차 부품이며, 임의 업종을 모두 지원한다고 표시하지 않는다.
6. **팀 서버 연결**은 설정으로 옮긴다. 접속할 서버와 전송될 자료·계정 경계를 설명하고 별도 로그인한다. 로컬 자료를 자동 동기화하거나 팀 GPU 설정을 변경하지 않는다.

## 모델과 전송·비용 표시

| 대상 | 현재 후보 및 근거 | 크기·비용·외부 전송 표시 |
|---|---|---|
| 주문 정리 | [Ollama qwen3:4b](https://ollama.com/library/qwen3:4b), Apache-2.0 | 공식 태그 페이지 약 2.5 GB. 모델 최초 다운로드만 외부 연결, 추론은 로컬. 유료 API 비용 없음. 메모리·전력·통신 사용은 별도 |
| 음성 전사 | [Systran/faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small/tree/main), 모델 카드 MIT | 공식 저장소 약 486 MB. 런타임·변환기 크기는 별도. 로컬 음성 처리, 유료 API 비용 없음 |
| 실행기 | 현재 Ollama·faster-whisper·Node 경계 유지 | 최종 배포할 각 바이너리·종속 라이브러리의 라이선스와 고지를 확정한다. 선택 개발 번들은 구현했으나 일반 사용자 배포는 미완료 |
| 선택 서버 | 사용자가 직접 지정한 팀 서버 | 업로드할 때 녹음·원문·업무 데이터가 해당 서버로 전달된다. 서버 운영 비용과 AI 제공자 비용은 그 설정에 따름 |
| 선택 외부 AI | 별도 명시적 기능으로만 검토 | 기본 꺼짐. 제공자·전송 항목·예상 비용·철회 방법을 안내해야 하며 현재 개발/테스트에서는 호출 금지 |

위 용량은 2026-11-18 공식 페이지의 참고값이며 설치기의 고정 용량 약속이 아니다. 현재 Whisper는 리비전·파일별 바이트·SHA-256·출처를 고정했다. 주문 모델도 준비 도구의 고정 메타데이터와 실제 배포 고지를 함께 검토하며, 이 문서의 참고값을 설치기 검증으로 대체하지 않는다. 두 모델은 약 3 GB 규모이나 실행기·압축 해제·업데이트 여유 공간과 RAM 요구량은 실측 후 따로 표시한다. 태그가 변경되었다고 실행 중 자동 교체하지 않는다.

## 구현 경계와 크리티컬 패스

1. **배포 런타임 확정**: Apple Silicon용 앱 전용 Ollama 및 전사 실행기, 오디오 변환 의존성을 배포 가능한 형태로 고정한다. 시스템 PATH·사용자 Python에 의존하지 않고 앱이 만든 프로세스만 관리한다. 현재 Mac 앱은 전용 `127.0.0.1:11435`와 소유 프로세스 확인·종료 경계를 구현했다. 기본 서버의11434 경로와 구분하며 사용자가 띄운 데몬을 대신 사용하지 않는다. 실행파일·플러그인은 서명된 앱 업데이트로 제공하고 최초 준비 단계에서는 검증된 모델 가중치만 받는다. Node 팀 서버 경로와 기존 GPU 워커는 그대로 둔다.
2. **모델 관리자**: 내려받기 manifest, 저장 공간 확인, 재개·취소, 체크섬 검증, 임시 파일의 원자적 교체, 이전 버전 복구를 구현한다. 외부 연결은 준비 단계의 승인된 모델 배포 주소로 제한한다.
3. **로컬 시작 흐름**: 로컬 소유자/업종 설정과 실행기 상태를 UI에 연결한다. 기존 웹 계정·작업공간 검증을 무력화하지 않고 로컬 소유자 생성에만 앱 전용 1회성 인증 경계를 설계한다. 재실행해도 같은 로컬 작업공간을 사용하고 세션과 일꾼 자격 증명을 자동 구성하여 outbox·SQLite 조회·worker.env 수동 편집을 제거한다.
4. **실제 추론 수용 시험**: 실제 가짜 음성으로 전사·카드·근거 질의·재시작 후 자료 보존을 확인한다. 시간·메모리·품질과 다운로드 이후 외부 연결 여부를 기록한다. fixture 시험과 다른 결과물로 관리한다.
5. **배포 서명·업데이트**: 중첩 실행기 서명·공증·설치본 무결성, 업데이트 실패 복구와 사용자 자료 보존을 검증한다. 이 검증 전에는 일반 사용자용 완성 설치판으로 발표하지 않는다.

## 릴리즈 체크리스트

- [ ] Node·Docker·Ollama·Python이 없는 깨끗한 Apple Silicon Mac에서 설치하고 첫 업무까지 터미널 없이 진행한다.
- [ ] 실제 배포 모델의 리비전·크기·체크섬·라이선스 고지와 모든 실행기 의존성을 확정한다.
- [ ] Lightning-SimulWhisper의 비상업 라이선스 코드를 포함하지 않았는지 확인한다.
- [ ] 모델 다운로드 취소·재개·오프라인·디스크 부족·손상·업데이트 실패 후 복구를 확인한다.
- [ ] 인터넷 차단 상태에서 가짜 음성 업로드→실제 전사→실제 주문 카드→근거 질문을 통과한다.
- [ ] 파일 한 개·여러 개 선택·취소, 저장/확정/출고, 앱 재시작과 종료 후 자식 프로세스 정리를 GUI로 확인한다.
- [ ] 로컬 사용 중 음성·원문 전송 없음과 유료 API 호출 없음을 실행 증거로 확인한다.
- [ ] 팀 서버 연결은 별도 선택이며 로컬 자료 자동 업로드·팀 GPU 설정 변경이 없음을 확인한다.
- [ ] 새 UI E2E·스크린샷·실모델 결과를 보고서에 넣고 Developer ID 서명·공증·설치/업데이트를 검증한다.

체크리스트의 미체크 항목은 현재 미완료다. [현재 빌드와 수동 준비 안내](mac-app.md)는 개발 검증용 경로로 유지한다.

### Whisper 파일 단위 재개 검증

모델 revision·파일명·크기·SHA-256을 포함한 manifest별 캐시에 **검증이 끝난 파일만** 보관한다. 다음 실행에서 다시 해시를 확인하고 설치용 독립 복사본을 만든다. 취소·네트워크 실패 중인 파일은 버리고 해당 파일은 처음부터 받는다. 모든 파일이 준비되기 전 기존 설치 목적지는 변경하지 않는다.

준비 도구 시험 23개, 전체 Mac helper 134개와 Node 175개를 통과했다. 실제 다운로드 없이 mock 전송으로 취소·재시도·손상·manifest 변경·symlink·동시 실행·목적지 충돌을 검사했다. 개발 앱/기존 ZIP 재빌드·교체는 하지 않았다.

한계: 큰 model.bin의 Range 재개는 미구현이다. 완료 캐시를 유지하므로 현재 모델 기준 추가 486,212,372바이트(약464MiB)를 사용하며 revision별로 누적될 수 있다. 준비 전 공간 검사는 전체 크기의 2배+64MiB로 보수적이며 이미 캐시가 있어도 이 기준을 적용한다. 강제 종료 후 남은 잠금의 자동 해제나 캐시 관리 UI는 구현하지 않았다. 일반 메뉴 재실행으로 파일 단위 재사용을 하지만 별도 일시정지 버튼은 없다.

### 주문 모델 파일 단위 재개 검증

검증 완료 blob을 기존 digest 기반 저장소에 no-overwrite 방식으로 게시한다. 취소·실패 후 다시 실행하면 해시를 재검사하여 완료 blob을 재사용한다. 부분 전송 파일은 지운다. 모든 blob과 실행기를 최종 검증하기 전에는 활성 manifest를 변경하지 않으며 이전 모델 blob·manifest 백업을 보존한다. 손상된 기존 blob과 symlink는 덮어쓰지 않고 거절한다.

준비 도구 27개, 전체 Mac helper 148개, Node 175개 시험을 통과했다. 모두 mock 전송이며 실제 다운로드는 하지 않았다. Whisper 전용 캐시와 달리 주문 모델은 기존 blob을 재사용하므로 별도 약2.5GB 복사본을 만들지 않는다. 다만 중단 후 미참조 완료 blob과 이전 모델 blob은 자동 삭제하지 않는다. 큰 blob의 중간 바이트 재개·자동 정리 UI·강제 종료 잠금 복구는 여전히 미완료다. 기존 앱·ZIP은 교체하지 않았다.

### 로컬 시작 안내의 범위

이동 → 이 Mac에서 시작 메뉴와 최초 준비 시트에서 계정·가입 인증·주문 모델·전사 모델·작업공간 연결·준비 상태의 6단계를 고른다. 선택은 기존 화면과 확인창을 여는 동작이다. 안내를 닫거나 취소해도 다운로드·가입·권한 연결이 시작되지 않으며 단계를 열었다고 완료로 기록하지 않는다.

### 준비 전 읽기 전용 Mac 점검

시작 안내 첫 단계와 별도 메뉴에서 OS·실행 아키텍처·물리 메모리·앱 자료 저장 볼륨의 남은 공간을 읽는다. 조회 실패는 확인 불가로 표시한다. 0바이트를 여유 충분으로 바꾸지 않으며 지원 여부를 자동 판정하지 않는다.

### 주문 모델 바이트 단위 재개

기본 주문 모델 다운로드에서 네트워크 중단·명시 취소 시 부분 파일과 digest/크기/부분 SHA 메타데이터를 별도 보관한다. 다음 실행은 부분 SHA를 확인한 뒤 남은 범위를 요청한다. 206의 범위·전체 크기·길이를 정확히 검사하며 200이면 처음부터 안전하게 다시 받는다. 416·잘못된 범위·과대 응답·인코딩·최종 SHA 실패는 설치하지 않는다. 모든 바이트의 고정 SHA가 맞아야 완료 blob으로 게시한다. 부분 SHA는 로컬 변경 탐지이며 게시자 무결성 증명이 아니다.

request 오류도 파일 쓰기 pipeline 종료 후 처리한다. 깨진 metadata는 해당 부분 캐시만 정리해 다음 호출을 허용한다. 디스크 필요량은 검증한 부분 바이트만 차감한다. 두 복구 결함은 독립 읽기 리뷰에서 발견한 뒤 수정·회귀했다.

모델43개·helper164개·Node175개 시험 통과. mock HTTPS만 사용했으므로 실제 CDN이 Range를 지원하는지는 확인하지 않았다. 취소 후 최대2.5GB 부분 SHA 기록이 잠시 걸릴 수 있다. 강제 종료의 stale lock 자동 해제·캐시 관리 UI·Whisper 바이트 재개는 미완료다. 앱/ZIP에는 아직 재빌드해 넣지 않았으며 실다운로드·배포는 하지 않았다.

### Whisper 바이트 재개와 공유 전송 엔진

Whisper도 기본 다운로드에서 부분 SHA·메타데이터를 검증하고 바이트 Range로 이어받는다. HTTP/부분 캐시 처리만 공통 모듈로 추출했고 Qwen digest 경로와 Hugging Face 고정 revision·정확한 CDN 객체 허용정책은 각 wrapper에 유지했다. 호출 옵션으로 정책을 덮어쓸 수 없다. 기존 완료 캐시와 설치용 독립 복사, 전체 SHA 확인, 기존 목적지 보존은 그대로다.

Whisper 설치 공간은 stage와 완료 캐시 양쪽을 확보하고 검증된 cache/partial 바이트만 차감한다. 합계·2배 공간 계산의 safe integer overflow도 거절한다. 앞 절의 Whisper ‘바이트 재개 미구현’과 ‘항상 전체2배 요구’는 이 변경으로 대체한다. 캐시 자동 정리·강제 종료 잠금 복구는 여전히 미완료다.

두 모델80개·helper178개·Node175개 시험 통과. 분리된 Resources fixture에 실제 helper를 복사해 두 모델 inspect를 별도 Node 프로세스로 실행했다. build.sh에는 공통 모듈 복사를 추가했다. 실제 앱/ZIP 재빌드는 하지 않았다. 모든 전송 시험은 mock HTTPS이므로 실제 HF/Ollama CDN Range 지원과 실제 대용량 취소 시간은 미검증이다.

### 모델 준비 강제 종료 잠금 복구

새 준비 도구는 macOS `/usr/bin/lockf`의 fd 잠금으로 두 모델 준비를 각각 직렬화한다. 파일 존재나 PID 재사용을 근거로 잠금을 깨지 않는다. kernel 파일은 삭제·교체하지 않고 Node가 fd를 보유한다. 프로세스가 종료되면 OS 잠금이 풀리며, 다음 실행은 같은 kernel inode와 정확한 새 owner marker가 확인되는 중단 상태만 복구한다.

기존 빈 잠금·불완전 marker·예상 밖 파일·symlink는 자동 삭제하지 않는다. marker 작성 중 강제 종료나 이전 버전의 빈 잠금은 여전히 수동 확인이 필요하다. 런타임 설치기 잠금은 이번 변경 대상이 아니다. stage 정리 실패에도 fd 해제를 보장하도록 독립 리뷰에서 찾은 문제를 수정했다. 영구 0바이트 kernel 파일이 남는 것은 정상이다.

현 Mac26.6.1 arm64에서 실제 임시 자식 SIGKILL·동시 복구·소유권 변경과 모델 mock 회귀92개, 전체 helper190개, Node175개를 통과했다. 사용자 모델이나 앱은 종료하지 않았다. Linux는 고정 `/usr/bin/flock` fd 모드를 사용하며 별도 Ubuntu focused CI를 추가했다. 실행기가 없거나 알 수 없는 OS면 fail closed한다. 이전 macOS·새 Mac 지원을 보장하지 않는다. 앱/ZIP 재빌드, 실제 CDN 다운로드·운영배포·병합은 하지 않았다.

### 모델·재개 캐시 저장공간 안내

이동 메뉴와 시작 안내의 Mac 점검에서 읽기 전용 공간 조회를 연다. 주문 blob·전사 모델 위치·각 부분 다운로드·완료 캐시를 구분하고 파일 내용 대신 메타데이터만 백그라운드에서 읽는다. dev/inode 기준 공유 파일은 위 항목부터 한 번만 계산하며 심볼릭 링크를 따라가지 않는다.

표시값은 논리 파일 크기다. APFS 실제 점유량이나 삭제 시 회수되는 공간이 아니며 설치 완료·무결성·재개 가능 판정도 아니다. manifest·실행기·설치 중 임시 폴더·기타 자료는 제외한다. 조회 실패·항목8000개·깊이64·크기 overflow는 확인 불가로 표시한다. 메뉴는 삭제·정리·다운로드를 제공하지 않는다.

Swift75검사·전체 native 컴파일·독립 읽기 리뷰 통과. 실제 GUI 클릭·앱 번들 반영은 미검증이다. 닫힌 시트나 다른 시트에 늦게 온 결과를 표시하지 않도록 현재 시트 동일성을 확인한다. 기존 앱·ZIP은 유지한다. 앞 잠금 복구 커밋부터 원격 push가 실행 승인 처리 오류로 막혀 있어 이 변경도 로컬에만 기록한다. 원격 CI 통과로 주장하지 않는다.
