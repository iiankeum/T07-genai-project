# [산출물 2] 아맞다 (Ah-matda) 개발 요청서

**요구사항 정의서 · 화면 설계서 · 기능 명세서**  
기준일 2026-11-16 · 첫 프로토타입 저장소 `main@604e4cd` · 현장 업무 데모는 같은 날 공개 배포본 기준

**두 데모의 적용 범위.** [화면 프로토타입](https://t07-product-prototypes.butterybeam16.chatgpt.site/callnote/)은 샘플 대화, 주문 카드 UX, 어시스턴트·공유 지식을 설명한다. [현장 업무 데모](https://t07.3-39-67-126.sslip.io/#/help)는 녹음 수집, 받아쓰기, 근거 청취, 확정과 출고를 설명한다. 두 호스트는 서로 다른 배포본이다.

**읽는 순서.** 2장은 첫 프로토타입(SCR-00~05A), 2.1은 현장 업무 데모(SCR-B01~B15), 3장은 운영 제안(SCR-P01~P07)이다. 화면명이나 기능이 비슷해도 검수는 해당 호스트와 화면 ID 조합으로 수행한다.

## 1. 범위·판독 기준

**서비스명 표기.** 정식 명칭은 **아맞다 (Ah-matda)**다. 제품 헤더·브라우저 제목·도움말·소개 페이지·홈 화면 설치 이름에는 국문명 **아맞다**를 사용하고, 영문 병기가 필요한 곳에는 **Ah-matda**로 적는다. 아래의 데모 표기는 관찰 당시 화면의 문구다.

- **지정 데모**는 통화 기록, 주문 보드, 오늘의 브리핑, 어시스턴트, 공유 지식의 5개 상위 메뉴를 갖는다. 아래의 화면 ID는 디자인·개발·검수용이다. 동일 페이지의 탭·패널·모달에 주소를 임의로 부여하지 않는다.
- **확인 방법**은 배포 화면의 초기 목록·탭·확정 차단·보드·브리핑·샘플 재생·어시스턴트·지식 편집창을 직접 열고, 배포된 HTML·JS·CSS의 나머지 이벤트와 조건 분기를 대조하는 방식이다. 모델 성공 응답은 서버 코드상 계약이며 지정 배포본에서 제안 요청은 모델 미연결로 종료되었다.
- **현재 동작**은 각 화면 표의 동작 열에, 실제 제품에서 달라져야 할 부분은 검수 열의 ‘상용’ 또는 별도 ‘추가 요구사항’에 명시했다. P0는 현장 파일럿의 선행 조건, P1은 후속 확장이다. 상용 화면의 주소·역할·우선순위는 설계 제안이다.
- **첫 프로토타입 데이터 기준**은 목록 샘플 5건이다. 초기 상태는 미확정 2, 재연락 1, 확정 2건이다. 상단의 통화 12·확정 8·확인 필요 3은 시연 숫자다. 문서 내 한빛모터스, 차번호·품번·통화 시각은 샘플이다.

### 4.3 개발 연계 계약

| 경계 | 입력 → 결과 | 예외·중복 처리 |
| --- | --- | --- |
| 지정 데모의 `POST /api/assistant` | message, 최근 일반 대화 최대 12개, 예시 통화와 승인 지식, 선택 통화 위치 → reply, suggestions, 선택적 knowledgeDraft | 서버는 잘못된 입력·권한 출처·빈 키·요청 제한·모델 실패를 오류로 반환한다. 프런트는 한국어 사유와 재시도를 제공한다. 모델 키는 서버에서만 사용한다. |
| 제안 · 파일 접수/작업 조회 | 허용 음원과 매장 → 통화 ID·작업 ID·단계·실패 사유 | 동일 파일 중복 제거, 작업 재개, 저장 성공 확인. 실패 단계 이후 재처리한다. |
| 제안 · 카드 저장/확정/출고 | 통화·주문 ID, 기대 버전, 품목·검토값, 반복 요청 방지 키 → 최신 버전·스냅숏·이벤트 ID | 권한 부족은 거절, 필수 누락은 필드별 이유, 기대 버전 불일치는 최신값과 병합 선택. 동일 키는 직전 결과를 돌려준다. |
| 제안 · 지식 제안/승인/복원 | 지식 ID, 기준 버전, 변경 내용·근거 → 검토안 또는 게시 버전 | 대표어 중복·권한·승인 대상 버전 재검사. 복원은 새 검토안 생성. |
| 제안 · 영업일 브리핑 | 매장·영업일·조회 시각 → 지표, 미처리 주문·재연락 참조, 복사용 원문 | 권한 범위의 동일 데이터로 카드·목록·복사본을 생성한다. 데이터 0건과 집계 실패를 별도 표기한다. |

### 4.4 릴리스 인수 시나리오

| 시나리오 | 수행 절차 | 합격 조건 |
| --- | --- | --- |
| AT-01 · 데모의 확정 경로 | 한빛모터스 → 주 버튼 → 차량 번호 확인 완료 → 주 버튼 → 품번 입력 → 수량 + → 주 버튼 → 확정된 주문 보기 | 처음에는 차번호, 다음은 품번 오류. 성공 후 출고 준비에 한빛모터스 2개가 보인다. |
| AT-02 · 데모 재생 | 새 통화 기록 → 일시 정지 → 기록 계속 → 기록 종료 | 정지 중 글자 증가 없음. 재개 시 같은 위치에서 진행. 종료 후 검수 가능. 조기 종료 품질은 G-02로 별도 시험. |
| AT-03 · 데모의 두 AI 경로 | 예시 대화 보기 → 재연락 문안 열기 → 수정·복사 → 현재 업무로 제안 받기 | 예시 표시·편집된 문안 복사. 성공은 실제 AI 라벨, 모델 미연결이면 오류·재시도. 자동 발송 0건. |
| AT-04 · 지식 검토 | 별칭과 출처 포함 신규 지식 저장 → 승인 → 수정 → 이력 복원 | 신규는 pending, 승인 뒤 참조 가능, 복원은 다시 pending. 상용은 마지막 게시본도 유지하며 두 브라우저에서 같은 버전을 본다. |
| AT-05 · 이력 재현 | 서로 다른 두 품목과 메모를 저장·확정 → 재로그인 → 출고 담당자가 열기 | 최종 품번·수량·메모·근거가 모두 같다. 상세→보드→원문 복귀 시 출고 상태가 회귀하지 않는다. |
| AT-06 · 중복과 장애 | 같은 녹음 2회 접수 → 전사 일꾼 중단·복귀 → 추출 실패 후 재시도 → 확정·출고 더블클릭 | 통화 1건·주문 1건·출고 이벤트 1건. 승인한 지식·사람이 수정한 필드는 유지한다. |
| AT-07 · 매장 경계·모바일 | 권한 없는 매장 주문 직접 열기, 이어서 375px에서 허용된 통화를 찾아 주문·브리핑 재연락 처리 | 권한 없는 데이터는 노출 0건. 허용된 업무는 하단 메뉴 또는 전체 메뉴로 끝까지 수행한다. |
| AT-08 · 마감 대사 | 자정 직전 주문을 다음 영업일에 확정 후 출고 → 완료 주문에 별도 재연락 추가 | 발생일·확정일·출고일 기준이 맞고, 브리핑·복사본이 일치한다. 재연락으로 주문이 미확정으로 바뀌지 않는다. |

### 4.5 현장 데모 기준의 추가 인수 시나리오

| 시나리오 | 입력과 수행 | 기대 결과 |
| --- | --- | --- |
| AT-09 · 수량 정정과 이의 제기 | 전날 새한카센터 앞범퍼 주문의 수량 근거 재생 → 같은 거래처의 다음 날 반품 통화 조회 | 원주문 2개와 반품 요청 1개를 서로 다른 통화·품목으로 추적한다. 수량이 다르다는 이유로 기존 기록을 덮어쓰지 않는다. |
| AT-10 · 미해결 정보와 재추출 | 좌우가 미정인 백미러 주문 → 질문이 남은 채 확정 시도 → 실제 확인 후 해결함 → 수량을 사람이 수정한 뒤 AI로 다시 정리 | 미해결 때는 확정 사유를 안내하고, 재추출 후에도 사람이 고친 수량은 유지한다. 확정 요건을 충족하면 보드에 반영한다. |
| AT-11 · 배송 문의와 출고 대사 | 부품이 없는 배송 문의의 처리를 마친 뒤 출고 목록의 대기 전체·오늘 확정 범위에서 조회 | 통화·거래처 이력에는 남고 물리 출고 품목에는 0행이다. 실제 확정 주문은 화면·인쇄·CSV 수량이 일치한다. |
| AT-12 · 전사 대기 | 가짜 예시 파일을 정책 안에서 접수하고 GPU 작업자가 꺼진 경우와 복귀한 경우를 각각 시험 | 초기에는 대기 상태로 남는다. 기존 통화 열람은 가능하다. 복귀 뒤 한 번만 받아쓰기·추출·검토 가능 상태로 전환한다. 이 경로의 종단간 실행은 후속 시험 대상이다. |
| AT-13 · 모바일 탐색·가독성 | 도움말 큰 글씨 설정 → 통화 탭 → 거래처 이력 → 더보기에서 출고 목록 → 다시 열기 | 글자 크기를 유지하고 모든 주요 화면에 도달한다. iOS·Android 홈 화면 추가는 각 OS의 안내 흐름으로 확인한다. |
