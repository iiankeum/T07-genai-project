# 모바일 검토 동선과 회귀 확장

## 바뀐 점
- 탭과 중복되는 주문 카드 제목은 화면에서만 감추고 영역 접근성 이름으로 유지했다. 상태·저장 안내·기본 정보 이동은 유지했다.
- 차량 맥락과 기본 정보 버튼을 같은 줄에 정리했다. 44px 터치 영역과 큰 글씨 반응을 유지했다.
- 제목과 빈 여백을 줄여 첫 품목이 하단 확정바 위에 보이는지 검사한다. 전체 기능이나 입력 필드를 제거하지 않았다.
- 모바일 근거 왕복을 별도 CI 단계로 연결했다.

## 자체 검증
별도 worktree 최종 코드에서 Node188, 디자인26뷰와 큰글씨13경로, 실제 임시 fixture 서버의 5/10품목×360/390px×일반/큰글씨8조건과 삭제경계2조건을 통과했다. 기존e2e10도 동일소스에서 통과했다. 앞품목 삭제로 index가 바뀌어도 stableID 대상에 복귀, 기억한 품목 삭제 시 다른 입력 대신 카드영역으로 복귀한다. 저장준비와 자동저장 경쟁은 실제 PATCH응답 대기로 분리했으며 테스트를 약화하지 않았다.

실제 사용자시험·전 화면 접근성 인증·실제 음성/AI 품질 검증은 아니다. 미선택 A/B 시안은 포함하지 않는다. dev 자동배포를 피하기 위해 배포 없는 통합브랜치 대상의 작은 후속 PR로 분리한다.
