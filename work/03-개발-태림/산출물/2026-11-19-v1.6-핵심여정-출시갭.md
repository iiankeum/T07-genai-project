## 우선순위
1. **새 고객 가입 경로:** 메일 공급자·발신 도메인·정책을 결정하고 실제 수신까지 시험. 임의 유료 공급자나 발신 계정을 만들지 않았다.
2. **새 기기에서 끝까지:** 승인된 새 Mac/팀 환경에서 가짜 녹음→실전사→초안→검토→확정→출고를 수행. 서명·런타임·권한·모델·품질을 한 번에 드러내는 시험이다.
3. **배포 전 자료 보존:** 실제 담당자가 최신 백업/복원·운영 env·기존 자료 연결을 확인. 확인 전 dev 머지 금지.
4. 성능·브라우저·접근성·현장 음성 평가. 더 많은 작은 UI 수정만으로 1~3이 완료되지 않는다.

## 이번에 구현한 안전한 우선 단계
`src/app/tools/release-readiness.mjs`와 `npm run check:release-readiness`를 추가했다. 환경설정으로 알 수 있는 데모·가짜 AI·꺼진 AI·메일 미구현과, 실제로 검증해야 하는 전사·백업·보안을 분리한다. **진단 도구이지 실제 연동을 완성한 기능은 아니다.** 현재 코드에서 출시 준비 완료를 표시하지 않고 종료코드2를 돌려준다.

- 함수는 파일·DB·네트워크·모델을 읽거나 호출하지 않는다. 입력 환경값·비밀·주소·이메일은 출력하지 않고 고정 문구만 낸다.
- `node --env-file=...`을 사용하면 Node 시작 단계가 지정 파일을 읽는다. 진단 함수 자체의 무파일 접근과 구분한다. 실제 운영 env는 이번 시험에서 읽지 않았다.
- 신규 단위 6개와 전체 Node 197개 통과. 독립 읽기 리뷰의 공백 처리 지적을 실제 auth 코드와 맞췄다.
- 기존 앱/데이터·실제 서버·네이티브 승인 대기를 바꾸지 않았다. 새 Mac·현장 품질·실제 메일이 해결됐다고 주장하지 않는다.
