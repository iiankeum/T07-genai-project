# 아차 백업·복원 검증

## 한 줄 결과

가짜 데이터 전체를 백업해 빈 폴더에 복원한 뒤, 다시 로그인하여 카드와 녹음을 읽고 권한이 유지됨을 확인했다. 운영 백업 구축 완료라는 뜻은 아니다.

## 검증한 것

- 독립 프로세스가 가짜 계정 3개와 작업공간 2개, 카드·받아쓰기·합성 WAV를 생성했다. 모든 DB 연결을 닫고 프로세스가 종료된 뒤 전체 디렉터리를 tar로 백업했다.
- 새 임시 디렉터리에 복원하고 실제 앱 HTTP 경로로 로그인했다. 카드·받아쓰기 내용과 WAV SHA-256 및 파일 권한이 유지됐다.
- 백업 후 원본 WAV를 바꾸어도 복원된 WAV는 백업 시점 내용이었다.
- 익명 접근은 401, 다른 작업공간의 카드·녹음은 404, 열람자의 카드 수정·내보내기와 무권한 공간 전환은 403이었다. 거절된 수정은 DB에 남지 않았다.
- 실제 사용자 자료, 실제 계정, 운영 서버, Docker 볼륨은 사용하거나 변경하지 않았다. AI 호출과 네트워크 외부 연결은 없다.

## 실행 및 범위

- 테스트: `src/app/test/backup-restore.test.mjs`
- 실행: `cd src/app && npm test`에 자동 포함한다. 기존 저장 실패 복구 테스트와 함께 `node --test test/backup-restore.test.mjs test/storage-recovery.test.mjs`로도 실행한다.
- 신규 복원 1개와 기존 저장 실패 복구 4개를 검증했다. 전체 Node 테스트 결과는 작업 일지에 기록한다.
- 변경은 검증 코드다. 앱에 자동 백업 기능을 추가하거나 운영 백업을 예약하지 않았다.

## 여전히 남은 것

REQ-NFR-06은 **부분** 상태를 유지한다. 실제 Docker 볼륨 복원, 서버 운영 중 일관성, 전원 차단, 암호화·외부 보관, 매일 자동 실행과 복구 목표 시간은 미검증이다. 백업에 계정 정보·세션·인증 링크가 포함될 수 있으므로 비밀 자료로 취급해야 한다. 이 테스트의 tar는 스스로 만든 가짜 자료이며 외부에서 받은 archive의 안전성을 보장하지 않는다.

운영 절차는 [설치 안내](../../../docs/self-hosting.md)의 중지 후 전체 볼륨 백업과 빈 볼륨 복원을 따른다. 원격 push 승인 차단으로 이 로컬 테스트의 원격 CI 실행은 아직 없다.
