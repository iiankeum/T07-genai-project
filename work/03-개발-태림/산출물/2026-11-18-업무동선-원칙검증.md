# 아맞다 업무 동선 개선 · 원칙과 실제 검증

작성: 신*림(taejs) · ChatGPT dot AI 초안. 실제 사용자 사용성 실험이 아닌 휴리스틱 검토와 가짜 데이터 기능 시험이다.

## 왜 토큰을 바꿔도 불편했나

이전 작업은 글꼴·간격·색을 정돈했지만, 자주 하는 주문·출고를 더보기 안에 두었다. 메인 화면에서는 통계를 먼저 읽어야 했고, 주문 검토 후 확정 버튼을 찾아 길게 내려가야 했다. 디자인 시스템의 외관만으로 업무 우선순위까지 해결되지는 않았다.

| 근거 | 실제 문제 | 이번 변경 | 검증 |
|---|---|---|---|
| Montage 일관성·확장성·개발 효율 | 페이지마다 목적보다 기능 목록이 앞섬 | 기존 컴포넌트 역할 유지, 주요 업무 탐색만 재편 | 기존 브라우저 여정 10개 통과 |
| Montage Bottom navigation: 주요 3~5개, 첫 깊이에서 사용 | 주문·출고가 더보기 뒤, 상세에도 전역 메뉴 | 오늘·통화·주문·출고·더보기, 상세는 현재 작업에 집중 | 주문·출고 각 1회 탭, 상세 하단 메뉴 숨김 |
| NN/g 인지 부담 최소화·점진적 공개 | 당장 처리할 일보다 요약 숫자가 먼저 | 작업 목록을 통계 위로 이동 | DOM 순서 및 첫 작업 화면 안 노출 |
| Montage Action area·Button 위계 | 확정 행동을 찾으려 긴 스크롤 | 모바일 주문 카드 하단 현재 행동 고정 | 버튼 화면 안, 마지막 입력 가림 없음, 대화 기록에서는 숨김 |
| Montage Card 접근성: 시각·DOM 순서 일치 | 업로드 설명의 DOM과 데스크톱 배치 순서 불일치 | 업로드 → 보조 정보 → 접힌 설명 순서 통일 | 소스 순서 확인, 업로드 동의·형식 검증 유지 |

## 확인한 범위

- 데스크톱 1440×1000·모바일 390×844, 핵심 화면 8개씩 총 16개 캡처. 가로 넘침 없음.
- 모바일 큰 글씨 8개 화면 가로 넘침 없음.
- 통화 상세에서 초안 확정은 기존 필수 확인 3건을 충족하기 전 비활성 상태 유지. 허가·확정 로직 변경 없음.
- 고정 행동 영역 아래 마지막 입력이 숨지 않는지, 대화 기록/카드 전환 시 버튼 노출이 맞는지 자동 검증.
- 녹음 파일의 잘못된 형식 차단 및 동의 전 업로드 차단 유지. 실제 고객 데이터·유료 API·녹음 전송 없음.
- Antigravity는 실제 생성에 사용하지 못했다. 기존 HTML/CSS 모듈을 직접 개선했으며 Montage React 컴포넌트로 전면 이식한 것은 아니다.

## 남은 확인

실제 사용자의 주문 검토 시간·오류율, iOS 실기기 키보드/확대/VoiceOver, native 앱 재빌드 후 같은 화면은 아직 확인하지 않았다. 자동 시험 통과를 사용성 만족으로 해석하지 않는다. 상세에서 진입한 주문 보드로 돌아가는 흐름 및 최초 실행 마법사는 다음 개선 후보다.
