# 아맞다 핵심 화면 재구성

## 범위
기획의 업로드 → 받아쓰기 → 주문 검토 → 확정 → 출고 흐름과 업무 보조·설정을 유지하면서 화면 구조를 다듬었다. 인증·워크스페이스·모델 처리·데이터 계약은 변경하지 않았다. Wanted React 컴포넌트로 갈아엎은 것이 아니라 기존 HTML 모듈을 재구성한 구현이다.

## 바뀐 사용 흐름
- **녹음 올리기**: 넓은 단일 폼 대신 왼쪽 파일·동의·올리기, 오른쪽 받아쓰기 연결·예시 녹음으로 나눈다. 처리 단계 설명은 접어서 필요할 때 읽는다. 동의 체크와 경고는 유지한다.
- **주문 보드**: 반복되는 큰 파랑/초록 버튼 대신 주문 내용을 먼저 읽는다. 상태별 점과 중립 배경으로 열을 구분한다. 상태명·확정/출고 동작과 확인 경계는 유지한다.
- **설정**: 링크만 나열한 빈 화면을 7개 목적별 카드로 바꾼다. 하위 설정은 데스크톱 좌측 메뉴, 모바일 가로 탐색으로 찾는다. 관리자 전용 연결/해제 폼과 권한은 변경하지 않는다.
- **어시스턴트**: 모바일에서 긴 업무 제안을 접고 대화 영역에 먼저 도달한다. 데스크톱은 펼친다. 화면 폭 경계에서 전환하고 접기 제어는 키보드로도 사용할 수 있다.
- **통화 검색·출고·실시간 기록·오늘**: 제목·본문·라벨·상태·버튼의 크기와 굵기를 통일한다. 출고 화면의 내부 요구 ID와 무조건 붙던 가짜 데모 문구를 일반 제목으로 바꾼다. 데모 여부는 상단 실제 데모 안내가 표시한다.

## 시각적 판단 근거
[Montage Typography](https://montage.wanted.co.kr/docs/foundations/base-material/typography)는 크기·행간·굵기로 위계를 만든다. [Foundations](https://montage.wanted.co.kr/docs/foundations)는 색상뿐 아니라 그리드·타이포그래피·깊이를 함께 다룬다. 여기서는 파란색을 늘리기보다 반복 버튼의 강도를 낮추고, 보조 정보와 실제 동작을 나누는 쪽을 선택했다. 이는 앱에 맞춘 설계 판단이며 공식 규정이라는 뜻은 아니다.

## 검증
- [시각 회귀](../자료/design-v2-after-20261118/results.json): 8화면×2크기 16개, 모바일 큰 글씨 8화면 가로 넘침 검사. 오프라인 로컬 글꼴 사용.
- 추가 상호작용: 모바일 어시스턴트 접기/펼치기, 잘못된 파일 거부, 업로드 동의 전/해제 후 차단, 설정 7카드와 화면 설정 이동. 업로드 파일은 가짜이며 실제 전송하지 않는다.
- [기존 E2E](../자료/design-v2-e2e-20261118/results.json): 주문 수정·근거·확정·출고·지식 승인·샘플 일시정지·인증·공간 격리 10흐름.
- Node 171개 통과. 유료 API·실제 마이크·고객 데이터·실제 사용자 공간 사용 없음.

## 남은 범위
- Antigravity 앱 선택 호출이 반환되지 않아 중단됐고 실제 Antigravity 생성 작업은 하지 못했다. 이 결과는 직접 HTML/CSS 작업이다.
- 현재 제품의 모든 관리·도움말 화면을 별도로 전면 교체한 것은 아니다. 핵심8화면 구조와 공통 스타일 개선이다.
- 사용자 취향 승인·새 Mac 실제 사용·서명 공증은 별도다. 현재 작업은 PR 검토용이며 운영 배포나 병합이 아니다.
- 새 네이티브 앱 번들은 기능 담당과 별도로 갱신한다. 브라우저 캡처를 새 앱 실행 증거로 대신하지 않는다.
