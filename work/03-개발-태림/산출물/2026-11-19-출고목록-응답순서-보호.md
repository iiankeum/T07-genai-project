# 출고 목록의 겹친 조회 보호

## 재현
같은 범위에서 새로고침 두 번을 겹쳐 실행했다. 최신 응답 뒤 과거 응답이 도착하면 화면이 과거 목록으로 되돌아갔다. 실제 shipping 모듈에 가짜 지연 API를 연결해 재현했다.

## 수정
- 조회마다 순번을 부여해 마지막 요청만 목록·오류·로딩 상태를 바꾼다.
- 전체→오늘→전체로 범위를 왕복해도 과거 요청을 구분한다.
- 출고 충돌 재조회의 후속 안내도 순번을 확인한다. 이전 응답이 최신 안내·출고 보류·키보드 초점을 덮지 않는다.
- 검토 중 최신 조회가 실패하면 ‘확인 중’ 대신 ‘출고 보류’를 안내한다.
- 기존 표시 버전(expectedRevision)·권한·API 계약은 변경하지 않는다.

## 검증
- 신규 실제 모듈+가짜 API 브라우저 회귀 8범위 통과. 역순 성공/실패, 최신 요청 대기 중 과거 성공/실패, 범위 왕복, 검토 후속 성공/실패, 언마운트를 검사했다. 오류·외부 요청 0건.
- 기존 임시 실제 fixture 서버 출고 버전 회귀 5범위 통과. 오래된 revision은 409, 최신 확인 후 명시 재시도는 정상 처리했다.
- Node 188개 통과. 독립 읽기 리뷰 및 주 검토를 진행했다.
