# 계정 메일 전송 경계: 최소 구현

**공급자 없는 로컬 계약 구현이다. 실제 계정 메일은 아직 outbox 파일 방식이며 외부에 발송되지 않는다.**

## 범위

- 별도 로컬 브랜치에서 공급자 중립 전송 경계와 테스트 전용 메모리 전송기를 작성했다.
- 기존 auth.mjs, 토큰 발급/검증/일회 사용, outbox 권한과 파일 포맷을 변경하지 않는다.
- 새 모듈은 실제 계정 경로에 연결하지 않는다. 환경 설정으로 켤 수 있는 외부 메일 모드를 추가하지 않는다.
- DB schema·마이그레이션·실서버·기존 데이터·실제 수신자·자격증명을 건드리지 않는다.

## 왜 분리했는가

기존 인증 트랜잭션은 동기다. 그 안에서 외부 전송을 기다리면 DB와 메일의 원자성을 잃는다. 따라서 먼저 템플릿·전송 결과·재시도 계약만 검증하며, 영속 큐와 연결은 별도 단계로 남긴다.

## 반드시 남아 있는 출시 차단

- 계정 트랜잭션과 함께 저장되는 암호화 큐, lease/fencing, 지속 재시도·횟수 제한·quota·취소 확인은 아직 없다.
- 메모리 가짜 전송기의 중복 방지는 프로세스 재시작이나 실제 공급자의 중복 방지를 보장하지 않는다.
- 전송 수락은 수신함 도착을 의미하지 않는다. 실제 메일은 중복 가능하며 exactly-once를 주장하지 않는다.
- 공급자·발신 도메인·키 보관·비용 상한·승인된 수신자 결정과 실제 수신 검증은 수행하지 않았다.
- Mac 연결과 GitHub 쓰기 권한 복구를 재시도하지 않았다. 이 작업은 미게시 로컬 변경이다.

## 계약에서 확인할 것

- verify/reset/invite만 받으며 템플릿과 링크 경로를 코드에서 만든다. 임의 제목·발신자·HTML·첨부를 받지 않는다.
- 수신 주소·43자 토큰·멱등 키·TTL·운영자가 지정한 HTTPS origin을 검증한다. 요청 Host를 읽지 않는다.
- 한 호출은 한 전송 시도다. 자동 재시도를 숨기지 않는다. 호출자가 같은 job과 같은 키로 명시적으로 재시도한다.
- 공급자 수락/명시 거절/수락 여부 불명/호출 전 차단을 분리한다. 예외 전문과 원문 응답은 반환하거나 로깅하지 않는다.
- 같은 키와 다른 메시지를 섞으면 가짜 전송기가 거절한다. 같은 키 재시도·동시 호출·수락 후 응답 유실을 가짜 메모리에서 시험한다.

## 검증 결과

- 신규 계약 테스트 13개와 기존 auth 6개 모두 통과했다. 전체 Node 테스트는 211개 통과했다(가짜 fixture 모듈의 자동 탐지 1개 포함).
- 명시 재시도·동시 중복·수락 후 응답 유실·동일 키의 다른 본문·만료·시작 전/후 취소·timeout·헤더/URL 검증·변하는 getter·잘못된 시계를 검증했다.
- 검토 중 찾은 비동기 키 재읽기, 허용값 검사 후 공급자 getter 재읽기, 전송 직전 만료/잘못된 시계 경계를 수정하고 회귀를 추가했다.
- 기존 auth/config/routes 파일의 diff가 없고, 새 모듈을 import하는 곳은 테스트뿐임을 확인했다.
- 브라우저/네이티브 화면·실제 공급자·수신함·영속 큐·재시작·실서버를 검증한 결과가 아니다.
