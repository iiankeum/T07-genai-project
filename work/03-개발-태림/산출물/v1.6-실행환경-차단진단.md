# 실행 환경 차단 진단

기존 구현 커밋 `54bbcb2`와 UI 커밋 `38da244`를 보존했다. 시작 시 작업트리가 깨끗했다. 이 회차에서는 E2E·네트워크 명령을 반복 시도하거나 앱을 직접 실행하는 대체 경로를 사용하지 않고, 정책과 시스템 상태를 읽었다.

## 승인 가능 여부

현재 실행 정책은 `approval_policy=granular`이며 `sandbox_approval=false`다. `require_escalated` 인자가 도구에 존재해도 이 세션에서 샌드박스 밖 실행 승인 요청은 허용되지 않는다. 실제 승인 요청을 보낸 뒤 거절된 사례와 다르다. 승인 불가 정책을 확인하여 요청하지 않았다. 다른 계정·자격 증명·프록시·DNS 변경으로 대신 접근하지 않았다.

## 확인 결과

| 검사 | 실제 결과 | 해석의 한계 |
|---|---|---|
| 이전 loopback bind/E2E | `listen EPERM`, 새 브라우저 흐름 0개 | 구현 실패나 새 UI 통과로 해석하지 않음. 이 회차 반복 실행 안 함 |
| `scutil --dns` | `No DNS configuration available` | 이 실행 환경에서 DNS 구성을 얻지 못함. Mac 전체의 DNS 장애로 단정 불가 |
| `dscacheutil -q host -a name github.com` | 결과 없음 | 이 환경의 resolver 조회 실패. 운영 네트워크 상태 미확정 |
| `scutil --nwi` | `nwi_state: registration failed (9)`, `No network information` | 시스템 네트워크 상태 서비스 접근 실패 |
| OS와 Antigravity | macOS 26.6.1 arm64, 앱 실행 파일 arm64, 최소 OS 13.0 | 아키텍처·최소 OS 불일치 없음 |
| 앱 파일·설정 | 실행 파일 있음, 0755, CFBundleExecutable 일치, Electron Framework 실제 파일 있음 | 단순 파일 부재/실행 비트 누락 아님 |
| `codesign --verify --deep --strict` | Antigravity와 Chrome 모두 `invalid signature` | 이 환경 공통 문제 가능성. Antigravity만 손상됐다고 단정 불가 |
| `codesign -d --verbose=4` | 서명·stapled ticket 메타데이터 존재, `Authority=(unavailable)` | 서명자 신뢰·공증 검증 성공을 뜻하지 않음 |
| `spctl --assess --type execute` | `internal error in Code Signing subsystem` | Gatekeeper의 명시적 악성 앱/미공증 판정이 아닌 검사 오류 |
| Antigravity 바이트 해시 대조 | CodeDirectory 코드 페이지 3개와 special slot 1·2·3·5·7의 SHA-256 모두 일치 | 서명 인증서·공증·모든 중첩 바이너리 검증을 대체하지 않음 |
| 앱 확장 속성 이름 조회 | `com.apple.provenance`만 출력 | 속성을 변경하지 않았으며 quarantine 제거도 수행하지 않음 |

해시 검사는 파일을 읽어 Mach-O의 LC_CODE_SIGNATURE와 내장 CodeDirectory에 기록된 코드 페이지·Info.plist·리소스 목록·요구사항·entitlements 해시를 비교했다. 서명 파일 자체의 진위를 인증하거나 모든 리소스 내용을 검증한 것은 아니다. 코드 서명 검사 오류를 무시하고 실행하는 데 사용하지 않았다.

**현재 가장 유력한 설명은 실행 환경의 시스템 서비스·네트워크 접근 제한이다.** 특히 시스템 네트워크 등록 실패와 두 앱의 동일한 서명 오류가 근거다. 다만 일반 터미널에서 비교하지 못했으므로 `-10827`의 단일 원인을 확정하지 않는다. Antigravity 로그인·모델·생성 기능은 사용하지 않았다.

## 필요한 사용자 조치

먼저 Mac의 일반 Terminal과 Finder에서 아래 읽기 검사로 비교한다. 보안 해제·재설치·관리자 권한은 필요하지 않다.

```sh
# 저장소가 있는 일반 Mac Terminal에서 실행
node -e 'const s=require("node:net").createServer();s.on("error",e=>{console.error(e.code);process.exitCode=1});s.listen(0,"127.0.0.1",()=>{console.log("loopback OK");s.close()})'
gh pr view 5 --repo iiankeum/T07-genai-project --json number,headRefName,headRefOid
codesign --verify --deep --strict --verbose=2 /Applications/Antigravity.app
```

Finder의 응용 프로그램에서 Antigravity를 평소처럼 연다. 경고가 나타나면 보안 설정을 변경하지 말고 문구를 기록한다.

- 일반 Terminal에서는 성공하면: 로컬 서버 실행·브라우저 실행·GitHub 네트워크를 허용하고 필요한 명령의 승인 요청이 가능한 실행 환경에서 이 checkout을 다시 연다. 현재 세션에서는 승인 정책을 자체 변경할 수 없다.
- 일반 Terminal에서도 GitHub 조회가 실패하면: Mac의 네트워크 연결·DNS 상태를 먼저 확인한다. 다른 계정의 토큰을 가져오지 않는다.
- 일반 Terminal에서도 Antigravity 서명 검사가 실패하면: 이 회차만으로 앱 손상을 확정하지 말고 검사 결과와 실행 경고를 공식 지원에 전달한다. 자동 재설치·재서명·quarantine 제거는 하지 않는다.
