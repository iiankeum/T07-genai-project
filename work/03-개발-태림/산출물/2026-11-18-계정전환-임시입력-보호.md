# 계정 전환 시 임시입력·요청자 보호

> AI 초안 · 돌린 사람: 신*림 · 도구: ChatGPT dot · 2026-11-18 21:26 KST

## 발견과 수정

v1.6 REQ-ERR-01/02, AUTH-06, NFR-04의 오류 복구·계정 경계를 점검했다. 전체 v1.6 완료를 뜻하지 않는다.

1. 기존 임시저장 키가 작업공간과 통화만 구분했다. 실제 카드 모듈+mock API 시험에서 A의 저장 실패 입력이 같은 작업공간 B의 재로그인 모의 화면에 복구되는 것을 재현했다. 새 키는 사용자·작업공간·통화를 각각 인코딩해 구분한다. 신원 없는 비공개 화면은 메모리만 사용한다.
2. 오래 열린 A 화면의 요청에 B 쿠키가 쓰이면 같은 작업공간 검사만으로는 막지 못했다. 가짜 DB와 실제 localhost HTTP에서 저장·내보내기·프로필 변경이 HTTP200인 것을 재현했다. 제품 요청은 최초 화면의 사용자 기대값을 유지하며 서버가 현재 쿠키 사용자와 다르면409로 거절한다.
3. 프로필·설정·비밀번호 변경·공간 생성/전환·초대 수락·로그아웃의 명시7경로에도 같은 기대값 검사를 적용했다. 로그인·가입·메일인증·비밀번호 재설정 같은 공개 인증 흐름은 그대로 둔다.
4. 음성·내보내기 URL query와 요청 header의 사용자/작업공간 기대값을 모두 확인한다. 새 header로 예전 URL을 덮을 수 없다. 알림은 계정 또는 작업공간 변경으로 안내한다.

## 보존과 한계

- 작성자를 알 수 없는 기존 임시저장 키는 **삭제·자동이관하지 않고 자동복구하지 않는다**. 따라서 업데이트 후 예전 미저장 입력은 자동으로 나타나지 않을 수 있다. 실제 사용자 저장소는 열거나 수정하지 않았다.
- 이 기대값은 인증 자격증명이 아니다. 기존 쿠키 인증·역할·출처 검사를 대체하거나 권한을 늘리지 않는다. 기대값 없는 legacy API와 기존 worker/ingest 호환은 유지한다.
- 같은 브라우저 저장소를 수동으로 읽는 공격까지 방어하는 암호화 기능은 아니다. 자동 복구·잘못된 계정으로의 요청 혼입을 막는 범위다.
- 실제 운영 계정, 모든 브라우저, 메일 전달, 기존 앱/원격 배포는 시험하지 않았다. 승인 오류로 push하지 않아 원격CI도 미실행이다.
