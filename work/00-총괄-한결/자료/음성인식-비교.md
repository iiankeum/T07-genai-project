# 음성 인식 비교 — 전화 주문 받아쓰기

킥오프에서 맡은 「음성 인식 방식 검토 — 갤럭시 통화 전사 vs Whisper 등 PC 안 모델, 품질 · 속도 비교」의 첫 정리다.

- **실측**이라고 적은 숫자만 우리가 직접 잰 것이다. 대표님 프로토타입(가짜 통화 10건)과 오늘 밤 해결사 방의 가짜 통화 54건으로 쟀다.
- 나머지 숫자는 조사 에이전트 3개가 모은 것이다. 출처는 각 조사 문서에 있다.
  - [조사 1 · PC 안 모델](음성인식-조사-1-PC모델.md)
  - [조사 2 · 클라우드 · 국내 서비스](음성인식-조사-2-클라우드-국내.md)
  - [조사 3 · 갤럭시 통화 녹음 · 받아쓰기](음성인식-조사-3-갤럭시.md)
- 정확도 숫자는 출처마다 자료와 계산 방법이 다르다. 같은 표 안에서만 비교한다.

## 한눈에 — 지금의 판단 (AI 판단 · 사람이 정할 것)

1. **데모 · 시범은 지금 구조를 그대로 쓴다.** 대표님 PC 의 GPU 에서 faster-whisper **large-v3** 로 받아쓰고, 서버의 Claude 가 거래처 목록 · 낱말 사전으로 고쳐 읽어 카드를 만든다.
   - 3분 통화를 13초 안팎에 받아쓴다(실측).
   - 거래처 이름(고유명사)은 더 빠른 turbo 보다 확실히 잘 알아듣는다. 54건 중 35건 대 27건이다.
2. **GPU 가 없는 현장 PC** 라면 large-v3-turbo 나 small 을 CPU 로 돌릴 수 있다.
   - 이 PC 의 CPU 로 잰 값은 3분 통화에 turbo 약 50초, small 약 27초다(실측 5건).
   - 대신 거래처 이름은 더 틀린다. 서버 쪽 고쳐 읽기에 더 기댄다.
3. **갤럭시 AI 의 통화 받아쓰기는 글을 자동으로 꺼낼 길이 없다**(조사 3). 통화마다 직원이 복사하거나 공유해야 한다.
   - 갤럭시는 통화 녹음 파일(m4a)을 정해진 폴더에 자동으로 남긴다.
   - 그래서 「녹음 폴더 → 서버 → PC 일꾼」(지금 만든 `src/pc-agent` 의 폴더 감시)이 현실적인 길이다.
4. **클라우드 · 국내 서비스는 실제 녹음 20~30건으로 직접 비교한 뒤 정한다.**
   - 후보는 리턴제로(RTZR), 네이버 CLOVA Speech, AWS 서울이다.
   - 월 50시간을 받아써도 5만~8만 원대라 비용 차이는 작다(조사 2).
   - 실제 통화를 해외 · 외부 서버로 보내려면 동의와 처리 위탁 절차가 먼저다.

## 1. 실측 — 오늘 밤 가짜 통화 54건 (2026-11-11)

### 조건

- **음성**: 해결사 방의 가짜 주문 통화 54건(합 46분, [src/demo-data](../../../src/demo-data/README.md))이다.
  - 합성 음성(edge-tts)을 8kHz 전화 음질로 낮춘 것(`phone`)과, 회선을 더 나쁘게 한 것(`noisy`) 두 가지다.
  - 7건에는 공장 소리(임팩 렌치 · 쇠 소리)가 섞여 있다.
- **도구**: [`src/pc-agent/bench_stt.py`](../../../src/pc-agent/bench_stt.py) — faster-whisper, 무음 거르기(VAD) 켬, 낱말 사전 힌트(`initial_prompt`) 켬. 일꾼과 같은 설정이다.
- **점수**: 받아쓴 글에 정답 카드의 낱말이 들어 있는지 센다. Claude 가 고쳐 읽기 **전**의 날것 점수다.
  - 부품: 품목 72개, 현장 말 · 표준 말 중 하나라도 있으면 맞음.
  - 차종: 차종 이름과 세대 코드가 모두 있어야 맞음, 44건.
  - 거래처: 이름 그대로 있어야 맞음, 53건.
- **PC**: RTX 5060 Ti 16GB · Ryzen 5 7500F(12스레드) · RAM 32GB.
  - 같은 GPU 에 받아쓰기 일꾼이 떠 있었고, 잴 때 시험 통화 몇 건을 같이 받아썼다. 시간이 조금 부풀었을 수 있다.

### 표 1 · 전화 음질 · GPU (54건)

| 모델 | 녹음 1분 받아쓰기 | 3분 통화 | GPU 메모리 | 부품 | 차종 | 거래처 |
|---|---|---|---|---|---|---|
| **large-v3** | 4.2초 | 12.6초 | 4.0GB | 69/72 | **31/44** | **35/53** |
| large-v3-turbo | 1.5초 | 4.5초 | 2.1GB | 68/72 | 27/44 | 27/53 |
| medium | 3.2초 | 9.7초 | 2.0GB | **71/72** | 29/44 | 31/53 |
| small | 2.0초 | 5.9초 | 1.0GB | 68/72 | 17/44 | 24/53 |

- 모델 올리는 데 3~7초 걸렸다(처음 내려받을 때 제외).
- **부품은 모든 모델이 거의 다 알아듣는다.** 차이는 거래처 이름과 차종 세대 코드(「NX4」 「DN8」 같은 것)에서 난다.
- turbo 는 large-v3 보다 2.8배 빠르지만 거래처 이름을 8건 더 틀린다. GPU 가 있으면 3분 통화에 13초와 5초의 차이라 사람이 느끼기 어렵다. 그래서 large-v3 를 그대로 쓴다.

### 표 2 · 낱말 사전 힌트가 도움이 되나 (전화 음질 · GPU)

| 모델 | 힌트 | 부품 | 차종 | 거래처 |
|---|---|---|---|---|
| large-v3 | 켬 | 69/72 | 31/44 | 35/53 |
| large-v3 | 끔 | 65/72 | 32/44 | 36/53 |
| large-v3-turbo | 켬 | 68/72 | 27/44 | 27/53 |
| large-v3-turbo | 끔 | 67/72 | 28/44 | 27/53 |

- 힌트는 부품 낱말에만 조금 도움이 되고(69 대 65), 거래처 · 차종에는 효과가 없다.
- 그래서 **거래처 이름은 받아쓰기가 아니라 서버의 카드 만들기(Claude + 거래처 목록)에서 고치는 것이 맞다.** 대표님 프로토타입도 같은 결론이었다(거래처 목록을 주면 7/10 → 9/10).

### 표 3 · 나쁜 회선 · GPU (54건)

| 모델 | 부품 | 차종 | 거래처 |
|---|---|---|---|
| large-v3 | 66/72 | 20/44 | 25/53 |
| large-v3-turbo | 59/72 | 19/44 | 23/53 |

- 회선이 나빠지면 거래처 · 차종이 크게 떨어진다(large-v3 거래처 35 → 25).
- 공장 소리 7건만 보면 large-v3 부품은 10/12 다(전화 음질 · 나쁜 회선 모두).

### 표 4 · GPU 없이 CPU 만 (전화 음질 5건 · 4분 38초)

| 모델 | 녹음 1분 받아쓰기 | 3분 통화 | 부품 | 차종 | 거래처 |
|---|---|---|---|---|---|
| large-v3-turbo (int8) | 16.7초 | 약 50초 | 11/11 | 3/5 | 4/5 |
| small (int8) | 8.9초 | 약 27초 | 11/11 | 3/5 | 4/5 |

5건뿐이라 정확도는 비교하지 못한다. 속도만 본다.

### 표 5 · 처음부터 끝까지 (서버 포함)

| 무엇 | 시간 |
|---|---|
| 가짜 통화 1건(나쁜 회선 · 48.9초)을 녹음 올리기 API 로 올림 → 사이트에 카드 | **19.3초**(받아쓰기 시작 2.4초 · 카드 만들기 시작 8.9초 · 완성 19.3초) |
| 해결사 방이 전화 음질 2건을 올림 | 약 30초 |

- 카드는 정답과 같았다(거래처 · 차종 · 연식 · 부품 · 수량).
- 받아쓰기 6.5초는 GPU 를 실측과 나눠 쓴 값이다. 나머지 약 10초는 서버의 Claude 카드 만들기다.

### 해결사 방 검수 (large-v3 · 무음 거르기 · 사전 힌트, 전화 음질 54건)

- 잘린 통화 0건이었다. 일꾼의 무음 거르기를 고치기 전에는 25건이었다.
- 무음 거르기를 통과한 말은 평균 98% 였다(공장 소리 통화는 63~83%).
- 거래처 35/53, 차번호 9/12, 품번 1/4.
- 「새한카센터」는 6건 모두 「세안카센터」로 받아썼다. 서버의 카드에서는 거래처 목록으로 고쳐진다.

### 대표님 프로토타입 실측 (가짜 통화 10건 · 2026-11-11 · 대표님 PC 의 call-order-card README · 저장소에는 아직 안 올림)

| 항목 | 결과 |
|---|---|
| 부품 · 수량 · 연식 · 급함 | 모든 조건에서 전부 맞음 |
| 거래처 | 7/10 → 거래처 목록을 주면 9/10 |
| 차번호 | 9/10(「육십칠 저 팔구공일」의 가운데 한글을 빠뜨림) |
| 카드 전체가 정답 | 5~8/10(조건에 따라) |
| 속도 | 10건(4분 41초)을 GPU 로 17초, CPU 로는 24초 통화 한 건에 28초 |

### 실측의 한계

- **합성 음성이다.** 사람보다 또박또박해서 실제 통화보다 쉽다. 웅얼거림 · 사투리 · 말 겹침 · 공장 소리는 실제가 훨씬 어렵다.
- 점수는 낱말이 들어 있는지만 본다. 글자 오류율(CER)은 대본이 숫자를 한글 소리로 적고 있어서(「이십일 년식」) 바로 잴 수 없었다.
- 같은 데이터로 프롬프트와 설정을 고쳤다. 새 통화에서는 점수가 내려갈 수 있다.

## 3. 현장에 놓는다면 — 녹음을 가져오는 길

| 녹음 장치 | 가져오는 길 | 상태 |
|---|---|---|
| 갤럭시 폰(국내 모델, 통화 녹음 기본) | `Recordings/Call` 의 m4a 를 PC 로 동기화(FolderSync · Syncthing 등) → `pc-agent watch` → 서버 | 프로그램 준비됨. 동기화 앱은 실기기 확인 필요(조사 3 · 5절) |
| 사무실 PC 통화 녹음 장치 · 녹음 폴더 | 그 폴더를 `pc-agent watch` 로 지켜봄 | 프로그램 준비됨 |
| 웹 화면 | 사이트에서 직접 올리기 · 브라우저 실시간 받아쓰기(체험) | 데모 사이트(개발 방) |

- 일반 앱은 안드로이드에서 통화를 직접 녹음할 수 없다. 삼성 전화 앱이 남긴 파일을 읽는 것만 된다(조사 3).
- 직원이 자기가 받는 통화를 녹음하는 것은 불법이 아니다. 다만 녹음 · 받아쓴 글을 다른 회사나 외부 서비스에 넘기려면 개인정보 보호법의 제3자 제공 · 처리 위탁 절차를 따라야 한다(조사 3 · 6절).
- 통화가 두 채널(우리 쪽 · 손님 쪽)로 녹음되면 화자 분리가 필요 없다. 한 채널이면 pyannote 등을 붙일 수 있다(조사 1).

## 4. 다음 할 일

1. 실제 녹음 20~30건(동의 · 가림 확인 뒤)으로 같은 표를 다시 잰다. 받아쓰기 점수와 카드 점수를 둘 다 본다.
2. 같은 녹음으로 RTZR · CLOVA Speech · AWS 서울을 비교한다. 시험 키 발급과 개인정보 처리 위탁 확인이 필요하다.
3. 갤럭시 실기기에서 녹음 파일 경로 · 이름 규칙과 폴더 동기화 앱을 확인한다(조사 3 · 8절).
4. 실시간 받아쓰기(통화 중 카드)의 가능성을 따로 본다. 브라우저 Web Speech API 체험은 데모 사이트에 있다. 서버 쪽 스트리밍(faster-whisper · RTZR · CLOVA 스트리밍)은 아직 확인하지 않았다.

## 아침 질문

- 받아쓰기 모델을 large-v3(정확, 지금)로 둘까요, turbo(2.8배 빠름, 거래처 이름 약함)로 바꿀까요? AI 는 large-v3 유지를 권한다.
- 실제 녹음 비교 때 클라우드 서비스(RTZR · CLOVA)도 시험해 볼까요? 비용은 몇천 원 안쪽이지만 대리점 동의와 처리 위탁 확인이 필요하다.
