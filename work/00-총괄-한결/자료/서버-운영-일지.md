## 3. 날짜별 기록

### 11/11 밤 — 서버 연결 · 자동 배포 · 녹음 보관소

자세한 과정은 [작업 기록](https://github.com/iiankeum/T07-genai-project/blob/dev/work/00-총괄-한결/LOG.md)(`dev` 가지)에 있다. 운영에 남는 것만 적는다.

- 데모 주소를 열고 HTTPS 인증서를 자동으로 받게 했다.
- `dev` 가지에 푸시하면 서버가 1분마다 확인해 새 버전을 띄운다. 새 버전이 30초 안에 응답하지 않으면 앞 버전으로 되돌린다.
- 시험: 좋은 커밋은 2초 만에 헬스체크를 통과했다. 일부러 깨뜨린 커밋은 30초 뒤 자동으로 되돌려졌다. 그동안 같은 서버의 다른 서비스는 응답 · 메모리가 그대로였다.
- 고장 1건: 윈도우에서 고친 실행 스크립트에 줄끝 문자(CR)가 붙어 앱이 약 1분 동안 「준비 중」 화면이었다. 고친 뒤 설치기에 그 문자를 지우는 줄을 넣었다.
- 녹음 보관소(S3 버킷)와 앱 전용 최소 권한 계정을 만들었다. 실제 녹음 자리(`real/`)는 어떤 키에도 권한을 주지 않았다.

개발 담당의 배포 요청을 받아 서버 관리자가 [PR #43](https://github.com/iiankeum/T07-genai-project/pull/43)을 `dev` 에 합쳤다. 아래는 그 PR 에 남긴 댓글과 배포 결과 화면에서 옮긴 것이다.

1. **데모 자료 백업.** DB · 녹음 · 환경 파일 사본을 서버의 관리자 전용 폴더에 두었다. 앱을 멈추지 않고 SQLite 백업 기능으로 떴다. DB 무결성 검사는 정상이었고 통화 62건 · 카드 62건이 들어 있었다.

## 4. 서버를 다룰 때 지킨 것

- **되돌리기 어려운 일은 사람이 먼저 허락한다.** 앱 멈추기 · 서버 설정 고치기 · 데모 자료 초기화는 서버 관리자(배\*결)가 구체적으로 허락한 뒤에만 AI 가 한다. 그래서 11/20 의 다시 채우기는 하지 않고 남겼다.
- **고치기 전에 백업한다.** 11/20 배포 전 DB · 녹음 · 환경 파일을 먼저 떴다.
- **비밀값은 이름만 적는다.** 환경 설정의 값 · 서버 주소 안쪽 경로 · 접속 방법은 PR 댓글과 문서에 쓰지 않는다.
- **같은 서버의 다른 서비스를 건드리지 않는다.** 데모 앱은 메모리 300MB 상한 안에서 돈다. 지금 68MB 를 쓴다.
