# 데모 서버 안내 — 콜노트(가칭)

7번 아이템 데모 사이트를 어디서 보고, 어떻게 올리고, 비밀값을 어떻게 지키는지 정리한 문서다.
서버 접속 정보(키 · 사용자명)와 비밀값은 이 문서에 없다 — 공개 저장소이기 때문이다.

## 1. 주소

| 무엇 | 주소 |
|---|---|
| 데모 사이트 | https://t07.3-39-67-126.sslip.io |
| 살아 있는지 | https://t07.3-39-67-126.sslip.io/healthz → `200` |
| 배포 결과 | https://t07.3-39-67-126.sslip.io/_deploy/status.json |

- 휴대폰 · 태블릿 · PC 어디서나 열린다. 자물쇠(HTTPS)는 Let's Encrypt 인증서를 서버가 알아서 받고 갱신한다.
- `sslip.io` 는 주소 안의 IP 로 바로 풀어 주는 무료 이름 서비스다. 정식 도메인이 생기면 주소만 바꾸면 된다.
- 앱이 아직 없거나 바꾸는 중이면 「준비 중」 안내 화면이 뜬다.

## 2. 올리는 법 — 「dev 에 푸시하면 끝」

1. 7번 제품 코드는 `src/app/` 에 둔다.
2. `dev` 가지에 푸시한다.
3. 서버가 1분마다 `dev` 끝 커밋을 확인해서, 새 커밋이면 받아서 띄운다. 보통 **푸시 뒤 1~2분** 안에 사이트에 반영된다.
4. 새 버전이 30초 안에 `/healthz` 에 200 을 주지 않으면 **앞 버전으로 자동으로 되돌린다.** 이유는 `status.json` 의 `last.log` · `last.appLog` 에 남는다.

서버에 들어가거나 GitHub 에 비밀값을 넣을 필요가 없다. 서버가 공개 저장소를 「당겨 가는」 방식이라서 그렇다.

### 배포 약속 v1 (개발 쪽이 지킬 것)

| 항목 | 약속 |
|---|---|
| 앱 위치 · 진입점 | `src/app/server.mjs` (Node 24, ESM). 서버는 저장소 뿌리에서 `node src/app/server.mjs` 로 띄운다. 파일 경로는 `import.meta.dirname` 기준으로 잡는다. |
| 빌드 | 없음. `src/app/package-lock.json` 이 있으면 `npm ci --omit=dev --ignore-scripts` 만 한다. |
| 패키지 | 네이티브 빌드가 필요한 패키지 금지(설치 스크립트를 돌리지 않는다). DB 는 Node 내장 `node:sqlite` 나 JSON 파일. |
| 포트 | `PORT`(5600) · `HOST`(127.0.0.1) 환경변수를 읽어서 듣는다. 바깥 요청은 Caddy 가 HTTPS 로 받아 넘겨 준다. |
| 헬스체크 | `GET /healthz` → 200. 시작 뒤 30초 안에 응답해야 한다. |
| 쓸 수 있는 곳 | `DATA_DIR`(`/var/lib/callnote`)와 앱 전용 `/tmp` 뿐. 코드 폴더를 포함한 나머지는 읽기 전용이다. |
| 메모리 | 앱 전체 300MB 상한(같은 서버의 다른 서비스를 지키려고). 녹음 파일은 통째로 메모리에 올리지 말고 스트림으로 다룬다. |
| 업로드 크기 | 요청 한 번에 60MB 까지(Caddy). 앱에서 더 작게 막아도 된다. |
| 환경변수 이름 | `PORT`, `HOST`, `DATA_DIR`, `PUBLIC_BASE_URL`, `ANTHROPIC_API_KEY`, `WORKER_TOKEN`, `INGEST_TOKEN`, `ADMIN_PASSCODE`, `S3_BUCKET`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |
| 로그 | 표준 출력으로 찍는다. 비밀값 · 환경변수 · 받아쓴 글 전문은 찍지 않는다(배포 실패 때 로그 끝 60줄이 공개 상태 화면에 실린다 — 비밀값은 서버가 한 번 더 가린다). |

### 개발 쪽이 하지 않을 것
- 서버 접속 · 서버 설정 변경(필요하면 한결 방에 요청한다).
- 저장소 · GitHub 설정에 키 · 토큰 · `.env` 올리기.
- `dev` 를 깨진 채로 두기 — 자동으로 되돌려지긴 하지만, 깨진 커밋을 고친 커밋을 바로 올린다.

## 3. 비밀값 관리 — 「API 키를 노출하지 않는 관리」

**원칙: 키는 서버 한 곳에만 둔다. 저장소 · GitHub · 브라우저 · 채팅에는 두지 않는다.**

| 비밀값 | 있는 곳 | 누가 쓰나 |
|---|---|---|
| Claude API 키 | 서버의 앱 환경변수 파일(관리자만 읽을 수 있음, 권한 0600) | 서버의 앱만. 브라우저는 키를 모르고 서버를 거쳐서만 AI 를 부른다. |
| 받아쓰기 일꾼 토큰 · 녹음 올리기 토큰 · 관리 암호 | 같은 파일. 서버에서 무작위로 만들었다. | 대표님 PC 의 받아쓰기 일꾼 · 녹음 전송 프로그램 |
| S3 접근 키 | 같은 파일 | 서버의 앱만(녹음 버킷의 정해진 폴더만 읽고 쓰는 최소 권한) |

- 대표님 PC 쪽 사본은 저장소 밖 비밀 폴더에만 둔다. 저장소의 `.gitignore` 와 GitHub 비밀값 검사(gitleaks)가 실수로 올라가는 것을 한 번 더 막는다.
- Claude API 키는 대표님이 **별도 워크스페이스 · 월 사용 한도**를 걸어 발급했다. 새어 나가도 피해가 그 한도 안에서 멈춘다.
- 앱은 전용 사용자로 갇혀 돈다. 공개 저장소의 코드가 자동으로 실행되므로, 혹시 뚫려도 같은 서버의 다른 서비스와 서버 전체로 번지지 않게 했다(다른 폴더 쓰기 금지 · 권한 상승 금지 · 메모리 · CPU 상한).

### 키를 바꾸는 법(교체)
1. Anthropic 콘솔에서 새 키를 만든다(같은 워크스페이스).
2. 서버 관리자(한결)가 서버의 앱 환경변수 파일에서 `ANTHROPIC_API_KEY=` 줄만 새 값으로 바꾸고 앱을 재시작한다.
3. 사이트에서 AI 기능이 되는지 확인한 뒤, 콘솔에서 옛 키를 지운다.
4. 토큰(일꾼 · 올리기)도 같은 방법으로 바꾸고, 대표님 PC 의 사본도 같이 바꾼다.

새어 나간 것이 의심되면 순서를 바꿔 **옛 키부터 바로 지운다**(사이트의 AI 기능은 새 키를 넣을 때까지 멈춘다).

## 4. 고장 났을 때 되돌리는 법

1. **가장 쉬운 길**: 문제 커밋을 `git revert` 해서 `dev` 에 푸시한다 → 1~2분 뒤 앞 상태로 돌아간다.
2. **자동**: 새 버전이 헬스체크를 통과하지 못하면 서버가 앞 버전으로 되돌린다(직접 할 일 없음). `status.json` 의 `last.result` 가 `rolled_back` 으로 보인다.
3. **서버 관리자만**: 서버에 남아 있는 최근 5개 버전 중 하나로 바로 바꿀 수 있다. 사이트가 아예 안 열리면 한결 방(서버 관리자)에 알린다.

## 5. 서버 구성(비밀값 제외)

- AWS Lightsail · 서울 리전 · Ubuntu 24.04 · 2 vCPU · 메모리 1GB. 같은 서버에 다른 실서비스가 함께 돌아서, 데모 앱은 메모리 · CPU 상한을 걸고 그 서비스는 건드리지 않는다.
- Caddy(HTTPS) → `127.0.0.1:5600` 의 데모 앱. Caddy 설정에는 데모 사이트 블록을 별도 파일로 **추가만** 했다.
- 자동 배포 장치(1분 타이머 · 헬스체크 · 되돌리기)는 서버에 있고, 저장소의 `ops/server/` 는 기록용 사본이다. 저장소에 푸시한 코드가 배포 장치를 바꾸지 못하게 하려는 것이다.
- 녹음 변환용 `ffmpeg` · `ffprobe`(6.1.1, `/usr/bin`)를 서버에 깔았다. 올라온 녹음은 서버 안(갇힌 앱)에서 16kHz mono WAV 로 바꾼 뒤 받아쓰기 일꾼에 넘긴다 — 인터넷에서 올라온 원본 파일을 대표님 PC 가 직접 열지 않게 하려는 것이다.
- 앱에는 지금 돌고 있는 커밋을 `GIT_COMMIT` 환경변수로 알려 준다(`/healthz` 에 보인다).

## 6. 만든 AWS 리소스

2026-11-11 밤에 서울 리전(ap-northeast-2)에 아래 두 개만 만들었다. 다른 리소스는 만들거나 지우지 않았다.
공개 저장소라 버킷 이름 끝의 무작위 글자와 계정 번호는 가렸다(전체 값은 서버 환경변수 파일과 대표님 PC 의 비밀 폴더에 있다).

| 리소스 | 이름 · ARN | 용도 · 설정 |
|---|---|---|
| S3 버킷 | `t07-callnote-rec-********` · `arn:aws:s3:::t07-callnote-rec-********` | 데모 녹음 보관. 공개 접근 4가지 모두 차단 · 기본 암호화(SSE-S3) · ACL 끔(버킷 소유자 강제) · HTTPS 아닌 요청 거부 · 다 못 올린 조각은 1일 뒤 정리 · `uploads/` 는 30일 뒤 자동 삭제 |
| IAM 사용자 | `arn:aws:iam::<계정 번호>:user/t07-callnote-app` | 데모 앱 서버 전용. 콘솔 로그인 없음 · 접근 키 1개(서버 환경변수 파일에만) |
| 그 사용자의 정책 | `t07-callnote-s3-demo-uploads`(인라인) | 위 버킷의 `demo/` · `uploads/` 아래만 읽기 · 쓰기 · 지우기 · 목록. 그 밖(`real/` 포함)은 모두 거부 |

버킷 폴더 약속:

| 접두사 | 무엇 | 오늘 권한 |
|---|---|---|
| `demo/` | 가짜 통화 음성 · 시연용 자료 | 앱 읽기 · 쓰기 |
| `uploads/` | 사이트 · 녹음 전송 프로그램으로 올라온 녹음 | 앱 읽기 · 쓰기, 30일 뒤 자동 삭제 |
| `real/` | 실제 통화 녹음(동의 · 가림 확인 뒤) | **어떤 키에도 권한 없음.** 내일 동의 · 가림 절차를 정한 뒤 따로 연다 |

권한 확인(앱 키로 직접 시험): `demo/` · `uploads/` 올리기 · 목록 · 지우기는 허용, `real/` · 버킷 뿌리 · 버킷 목록은 `AccessDenied`, 바깥에서 주소로 열기는 403.

**지금 데모 사이트는 이 버킷을 쓰지 않는다**(개발 방 결정 2026-11-11 — 의존성과 메모리를 늘리지 않으려고). 녹음 · DB 는 서버 디스크의 데이터 폴더에 있다. 버킷은 실제 녹음을 받을 때 쓰려고 남겨 둔다.

## 7. 받아쓰기 일꾼 (대표님 PC)

- Claude API 는 음성을 받아쓰지 못한다. 그래서 받아쓰기는 대표님 PC 의 GPU(RTX 5060 Ti)에서 Whisper large-v3 로 한다. 프로그램은 [`src/pc-agent/`](../../src/pc-agent/README.md)(`dev` 가지)에 있다.
- 일꾼이 서버에 접속해 일감을 가져가는 방식이라, 대표님 PC 는 방화벽을 열 필요가 없다. 일꾼은 서버가 16kHz WAV 로 바꾼 파일만 받는다.
- 켜져 있는지는 https://t07.3-39-67-126.sslip.io/api/worker/status 의 `online` 으로 본다. 꺼져 있으면 사이트에 「받아쓰기 일꾼 대기 중」이 뜨고, 올라온 녹음은 줄을 서서 기다렸다가 일꾼이 켜지면 받아써진다.
- 2026-11-11 밤 시험: 가짜 통화 1건(49초)을 올리고 사이트에 주문 카드가 뜨기까지 19.3초였다. 속도 · 정확도 비교는 [음성인식-비교.md](자료/음성인식-비교.md)(`dev` 가지)에 있다.
- 켜는 법(대표님 PC, 저장소 폴더에서): `src\pc-agent\.venv\Scripts\python src\pc-agent\callnote_agent.py worker --name gpu-pc-1`. 재부팅 때 자동으로 켜는 설정은 아직 없다.

## 아침 질문
- 받아쓰기 일꾼을 PC 를 켤 때 자동으로 켤까요? 지금은 터미널 창에서 손으로 켠다(밤새 켜 둠).
- S3 버킷은 `uploads/` 를 30일 뒤 자동으로 지우게 해 두었다(지금 데모는 버킷을 쓰지 않음). 실제 녹음을 받을 때 보관 기간을 정해야 한다.
- 정식 도메인을 쓸까요? 지금은 무료 이름(`sslip.io`)이다. 발표 때 주소가 길면 짧은 도메인을 사서 연결할 수 있다(연결은 10분이면 된다).
